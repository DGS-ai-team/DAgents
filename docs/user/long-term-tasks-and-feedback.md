# 长期任务与用户反馈

## 长期任务

Agent 分为普通 Agent 和自主 Agent（Auto Agent）。创建智能体时选择类型；已有智能体可在“设置 → 智能体列表 → 基本设置”修改类型。自主 Agent 的“自主任务”页签用于配置目标、完成条件、运行次数、累计与单轮 Token 预算、截止时间和最小唤醒间隔。新建自主 Agent 不会自动执行，需先配置并启用任务。

自主 Agent 空闲时可以像普通 Agent 一样在主聊天中对话。可以要求它查看任务，或修改目标、完成条件、下次唤醒时间，也可以要求暂停；修改通过工具实际保存，设置页可刷新核对。它不能自行提高预算、运行次数或唤醒频率上限，也不能重置已经消耗的用量。聊天页提供“自主任务设置”入口。

目标通过当前 Node 的调度器定期唤醒。Node 必须保持运行；这不是云端常驻服务。每个目标使用所属 Agent 的模型、工具权限和专用会话。同一 Agent 有活动任务或审批等待时，后续唤醒延后；不同 Agent 可以并行。

查看运行历史、最新进度与证据判断结果。专用会话用于查看历史、处理审批和取消当前执行；日常对话和调整任务使用 Agent 主聊天。只有模型保存完成证据且对应执行成功结束，目标才显示完成。旧版“长期任务”页面继续保留历史记录。

“暂停”阻止后续运行，当前轮次仍可收尾；“停止”还会取消当前执行。达到次数或预算上限、连续无进展时会暂停。重启时未完成的执行保守标记为未知，不能直接恢复以重复副作用；需要人工核对执行记录及外部结果。

当前版本每个 Auto Agent 绑定一份自主任务。任务完成或停止后不能在该 Agent 内开始新周期，需要创建新的 Auto Agent；任务周期复用属于后续规划。主聊天修改工具不能创建、重新启用任务或提高授权限额，首次配置和启用请使用智能体设置。

旧 Goal 创建接口不再接受新任务，API 集成应使用 `PUT /v1/agents/{agent_id}/autonomy`。旧记录保留查看、暂停与停止；不属于 Auto 配置的旧任务不能从历史页重新唤醒。缺省类型仍为普通，切回普通类型后不会继续获得自主执行能力。

Token 阈值根据模型实际报告的用量在请求边界检查。正在进行的单次模型请求可能超过阈值，因此预算不是精确费用封顶。模型不报告用量时，任务暂停以避免继续累积未知消耗。复杂目标需要合理预算；本次隔离验证中，简单文件任务也使用了约 1.6 万 Token。

## 用户反馈

在 Node 设置中打开“反馈”，填写类型、标题和正文。反馈发送给创建记录时当前 Node 连接的 Manage 管理员，只提交用户填写的内容。

“已保存，等待发送”表示记录已在 Node 本地保存；Manage 确认入库后才显示送达。离线时保留记录并重试。未配置 Manage 时可保留草稿；切换 Manage 地址或 Node 身份后，旧记录不会自动转发给新的管理员。

管理员在 Manage 的反馈页面筛选意见、回复并修改处理状态。Node 同步后显示管理员回复。送达状态与处理状态分别展示；多次重试不会覆盖管理员回复或产生重复反馈。
