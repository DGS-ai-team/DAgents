# 自主智能体

自主智能体（Auto）会按设置的频率检查是否有工作需要推进。聊天和自主激活使用同一个主会话，你可以在工作过程中继续补充要求或纠正任务。

## 设置职责和激活频率

进入「设置 → 智能体」，选择自主智能体并打开自主设置。

- **职责**：说明它长期负责什么，作为每轮系统提示的一部分。修改后在下一轮生效。
- **自主激活频率**：可以关闭、选择预设间隔或自定义秒数。关闭默认唤醒不会禁止普通聊天，也不会关闭其他单独创建的触发器。
- **最大工具轮次**：限制一次自主工作的工具调用循环；达到上限后允许模型做一次不调用工具的收尾。
- **待办**：在聊天页展开查看。用户与智能体可以编辑同一份待办；出现版本冲突时应重新读取后再修改。

激活频率对应这个智能体的系统默认触发器。频率从自主设置修改。如果配置已保存但触发器同步失败，使用「同步唤醒」重试，不需要再次提交职责或待办。

## 每日经验整理

开启每日 dreaming 后，设置整理时间与时区。它独立于默认激活频率：即使关闭默认唤醒，仍可以每天整理经验。

整理会参考近期上下文、已有经验和待办。较长内容可以写入手册目录，并在经验中保留摘要与相对路径索引。手册使用文件系统，智能体可以按需要建立目录层级；文件操作仍受现有工具权限与审批约束。

手册目录留空时使用智能体自己的默认目录；相对目录以智能体状态目录为基准，绝对目录使用指定位置。模型通过 `handbook/...` 读取、写入和搜索文件，目录放在工作区外也使用相同路径形式。

需要工具审批时，在原聊天会话中处理。连续多次审批仍属于同一次整理；拒绝或取消不会提交本次经验。整理完成后保留固定上下文边界，之后新发的用户消息不会被延迟收尾清除。

经验仅由成功完成的 dreaming 更新，之后的新一轮会使用更新后的经验。成功整理会重置模型使用的活跃上下文，但保留会话身份、可查聊天历史和待办。失败不会以清空聊天记录作为处理方式。

## 查看与处理恢复状态

Node 的 Auto 总览显示激活状态、待办和 dreaming 状态。Manage 显示 Node 上报的状态与数量摘要，并标明上报时间；经验和待办正文不会随这份摘要上传。

需要区分两类恢复：

- **默认唤醒需要核对**：在自主设置中打开「在新页面管理定时任务」，核查旧投递后再确认丢弃。原设置页的未保存草稿保留。返回后刷新默认唤醒状态，必要时重新同步频率。
- **Dreaming 等待恢复**：经验提交后的上下文重置尚未确认，由每日整理调度处理。这不是触发器投递，不应通过丢弃触发器来解决。

旧投递处于待恢复状态时，该触发器被冻结；其他智能体仍可使用。不要把未确认的旧投递当作未执行而重复运行外部命令。

## 条件脚本

触发器的 `condition.cmd` 可在唤醒前运行检查脚本。脚本执行使用所属智能体的工具环境与原有审批：需要审批时先等待用户处理，批准才执行。条件检查本身不调用模型；脚本成功退出（退出码 0）才投递原任务，条件不满足则不唤醒。

审批等待期间若触发器已关闭、修改或进入恢复状态，旧审批不能继续执行原脚本。投递结果不确定时保留恢复记录，不自动重复脚本。只读检查应避免产生外部副作用，以便后续定期检查。

## 没有工作时的通知

默认自主激活检查后，如果没有需要推进的工作，智能体可以通过 `auto_idle` 结束本轮。系统保留激活输入和工具记录，但不增加本轮的未读完成通知。普通聊天中说“没有工作”仍是正常回复，不会因为文字内容被静默处理。

这个结束信号只对系统验证过的自主激活开放。已执行写入、发生工具失败或请求过审批的回合不能用它静默结束；普通聊天、其他触发器与其他智能体也不能借用该信号。原有工具审批规则继续生效。

关闭每日 dreaming 只停止后续调度；已经成功完成的时间仍会显示，包括第二天等待、失败或重启后的状态。
