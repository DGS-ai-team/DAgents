# DAgents Web UI 产品级设计评审与重构基线

> 状态：核心改造已落地，持续精修
> 适用范围：Node 内嵌 Web UI，Windows / Linux 桌面环境
> 评审基线：2026-08-30，覆盖当前工作区改造
> 目标：在不扩大产品边界的前提下，将当前“功能完整的工程控制台”提升为“稳定、统一、高效的桌面 Agent 产品”。

## 1. 结论

当前 UI 已经能承载对话、工具执行、审批、终端、Agent 配置和系统设置，功能覆盖并不弱；真正拉低产品完成度的不是某一个组件，而是缺少统一的页面密度、动作层级、状态占位和设计令牌约束。

以商业产品标准衡量，当前整体约为 **5.8 / 10**：已经越过“开发者 Demo”，但仍明显带有多人持续叠加功能后的工程界面感。主要表现为：核心工作区和设置页像两套产品；终端页的空间关系不稳定；设置页大量留白但信息仍不易扫描；相同动作在不同页面采用按钮、文字链接和行内操作等不同表达；样式规模已经超过当前设计系统的约束能力。

优点也很明确：整体视觉克制，没有滥用高饱和色；Agent 对话主路径清楚；工具卡片已经开始遵循“只展示用户关心的信息”；设置侧栏的分组比旧版清晰；浅色和深色主题都有可用基础。这些都值得保留。

### 1.1 评分

| 维度 | 评分 | 判断 |
| --- | ---: | --- |
| 信息架构 | 6.0 | 大类可理解，但“全局配置、当前 Agent、当前会话”仍有混用 |
| 视觉层级 | 5.5 | 标题和区块存在，页面焦点与主要动作不够明确 |
| 一致性 | 5.0 | 页头、保存、刷新、空状态、卡片和状态标签规则不统一 |
| 操作效率 | 6.0 | 核心路径可达，长配置页和低信息密度增加扫描成本 |
| 状态反馈 | 5.5 | 能显示运行状态，但部分状态会改变布局，空态也有错误引导 |
| 桌面空间利用 | 5.5 | 宽屏留白过多，终端与 Agent 面板比例不够稳定 |
| 无障碍基础 | 6.0 | 多数图标按钮有标题或 aria，但字号、焦点和对比仍不成体系 |
| 视觉气质 | 6.0 | 中性、克制，但过于平、碎、灰，缺少精确的节奏感 |
| 前端可维护性 | 4.5 | 样式体量和硬编码值已经妨碍长期统一 |
| 产品就绪度 | 5.8 | 可用，但尚未达到对外发布时应有的稳定与精致程度 |

## 2. 已确认的产品约束

后续改版不得破坏以下已经确认的方向：

1. 目标环境是有桌面的 Windows / Linux，不以移动端为设计目标；主要验收宽度为 1366、1600、1920。
2. Agent 主页面的输入栏位置及其下方资源按钮位置保持不动，只修复尺寸抖动、视觉关系和状态表达。
3. 输入栏左下方只展示当前 Agent 绑定的 MCP 服务、当前 Agent 激活的终端和绑定的 Skills。
4. 上述资源面板保持只读和简约；只有终端条目允许点击跳转。
5. 工具卡片只展示用户决策所需的信息；执行目的放在标题中，不重复为表单字段；代码块只保留复制，不提供下载。
6. 终端页以终端为主，但必须保留可见的 Agent 输出和给 Agent 发消息的入口。
7. Workgroup 未启用时必须隐藏，不向用户展示不可用入口或半成品空状态。
8. Skills 元数据只在新会话或上下文重建时进入 system prompt；会话中变更通过事件通知，模型按需调用 `list_available_skills` 获取最新列表。UI 不应继续强化旧的 load / unload 心智模型。
9. 不恢复已移除的活动页，也不增加新的“总览仪表盘”来转移现有信息架构问题。

## 3. 评审证据

本次在 1787 × 1216 的真实运行页面中检查了 Agent 对话、终端工作台、Workgroup 关闭态，以及通用、模型与连接、MCP、Linux 通道、能力、Skills、Agent 列表、Agent 详情、定时任务、输出防护、上下文和关于页面，并对照了布局组件与样式实现。

可量化的现状包括：

- 设置主区域约 1503 px 宽，实际内容限制在 1120–1180 px，又被放进一个占满视口的大卡片中，形成“宽屏很空、内容仍不紧凑”的双重浪费。
- `workbench.css` 已约 4092 行；静态扫描可见约 414 处十六进制颜色、461 处字号声明、260 处圆角声明，字号取值超过 30 种、圆角取值超过 20 种。即使其中包含主题和兼容回退，也说明令牌没有真正成为约束。
- Agent 详情页没有复用统一页头，且把行为、记忆、MCP、Linux 通道和工具策略串在同一长页面中。
- 输入栏运行状态使用条件渲染；状态出现时至少新增 16 px 高度和边距，会直接挤压消息区或终端区。
- Workgroup 关闭时，侧栏入口虽然隐藏，但直接访问 `/workgroups` 仍显示“点击 + 新建”，页面上却没有可执行的 `+`，属于错误空状态。
- Skills 页面位于全局设置，却展示“当前智能体”和 Agent ID，范围语义不清；“已加载 / 技能目录”也与新的 Skills 生命周期设计不一致。
- 终端页在没有会话时保留大面积空白；Agent 面板默认占 31%，长消息、表格和工具卡片被压缩，而底部输入栏又横跨整个工作区，发送对象不够明确。

## 4. 必须优先解决的问题

这里的 P0 / P1 是产品验收优先级，不代表线上事故等级。

### P0：产品验收前必须修复

#### P0-1 输入栏状态导致布局抖动

当前 `runtimeStatusText` 出现或消失会改变输入区高度，进而挤压 Agent 消息和终端区域。状态变化越频繁，界面越像在“跳”。

目标：输入区从空闲到生成、调用工具、等待审批、取消中，外框几何尺寸保持不变。为状态预留固定 18 px 槽位，或将状态绝对定位在输入框右上方；禁止通过 `v-if` 改变输入区占用高度。

验收：在同一窗口录制状态切换，输入栏顶部 Y 坐标变化不超过 1 px，消息区与终端区不发生可见位移。

#### P0-2 Workgroup 关闭态不完整

目标：未配置或未启用 Workgroup 时：

- Agent 侧栏不出现 Workgroup 切换入口；
- 直接访问 `/workgroups` 时路由守卫返回 Agent 页面，并给出一次轻提示“工作组未启用”；
- 不渲染“点击 + 新建”这类不可执行文案。

#### P0-3 Skills 页面仍在表达旧生命周期

目标：全局 Skills 页面表达“已发现 / 已安装的技能目录”，Agent 详情表达“该 Agent 可见的技能范围”。移除面向用户的 load / unload 状态，不显示 Agent ID。页面需要明确提示：当前会话的 system prompt 元数据不会实时重写；变更会通知模型，模型可按需刷新列表；新会话或上下文重建后自然进入新快照。

### P1：影响核心效率与一致性

#### P1-1 终端页的三层关系不清

终端会话、Agent 消息和 Agent 输入都重要，但当前缺少清晰的主次和归属提示。目标结构见第 6.2 节。

#### P1-2 设置页动作模型不统一

“保存”有时是蓝色按钮，有时是底部悬浮条；“刷新 / 重新加载”有时是页头文字，有时是行内文字；“新增”有时是主按钮，有时只是文字。用户必须逐页重新学习。

目标规则：

- 每页最多一个主动作；新增类页面的主动作固定在页头右侧。
- 有未保存表单时，使用统一的底部粘性操作条；没有修改时不常驻。
- 刷新属于次要图标按钮，放在页头右侧并带 Tooltip。
- 行项目只保留与该项目直接相关的操作，默认收进 `…` 菜单；破坏性操作必须二次确认。

#### P1-3 设置页密度低但扫描成本高

大面积空白不是高级感。当前问题是信息没有被组织成可扫描的行和列：字段组之间很远，标签与控件关系弱，内容区又被大卡片套住。

目标：设置页使用 960 px 默认内容宽度、1080 px 上限；简单字段使用两列栅格，长文本和代码使用整行；相邻字段组间距 20–24 px，区块间距 32 px。移除包住整个页面的白色大卡片，只在确有边界的列表、代码和危险区域使用卡片。

#### P1-4 Agent 详情页过长且保存边界模糊

目标：将 Agent 详情拆成独立页签或锚点路由：

- 基础与模型
- 角色与记忆
- MCP 与 Skills
- Linux 通道
- 工具与审批

每个页签只有一个保存边界。顶部页签保持可见，底部操作条只在发生修改时出现。禁止同时出现“保存并应用”“重新加载”和各区块独立“保存”而没有清晰优先级。

### P2：视觉系统与长期质量

- 收敛颜色、字号、圆角、阴影和间距令牌，禁止组件自行发明相近值。
- 统一中文产品文案，`ready`、`health ok`、`THINKING`、`MANAGE 上传` 等技术词只在开发者信息中保留。
- 默认正文不小于 13 px，关键状态和可点击文本不小于 12 px；8–11 px 只允许用于非关键徽标。
- 浅色主题减少“白底套白卡”；深色主题增加层级差，避免主内容、卡片和输入区都落在近似黑灰色上。
- 所有图标按钮必须有 Tooltip、可见焦点环和稳定的 30–32 px 点击区域。

## 5. 目标设计系统

### 5.1 视觉原则

1. **终端与内容优先**：装饰不得抢占工作空间。
2. **紧凑但不拥挤**：依靠网格和层级提高密度，不依靠缩小字号。
3. **状态不改变布局**：生成、审批、加载和错误都必须有固定容器。
4. **范围先于功能**：先告诉用户这是全局、Agent 还是会话级，再展示配置。
5. **一个页面一个主动作**：避免并列的多个蓝色按钮。
6. **技术细节按需展开**：ID、原始 JSON、内部状态进入“高级 / 诊断”，不占据默认首屏。

### 5.2 基础令牌

| 类型 | 建议值 |
| --- | --- |
| 字号 | 12 辅助、13 次正文、14 正文、16 区块标题、22 页面标题 |
| 行高 | 正文 1.55，辅助 1.45，标题 1.3 |
| 间距 | 4、8、12、16、24、32 |
| 控件高度 | 紧凑 28、默认 32、强调 36 |
| 圆角 | 4 小控件、6 默认控件、10 容器；999 仅徽标和圆形按钮 |
| 阴影 | 只允许浮层和粘性操作条使用；普通卡片依靠边框和背景层级 |
| 内容宽度 | 对话 860–960；设置默认 960、最大 1080 |
| 侧栏 | Agent 248；设置 220 |

新增语义令牌：

- `--surface-app`、`--surface-panel`、`--surface-raised`、`--surface-code`
- `--text-primary`、`--text-secondary`、`--text-tertiary`
- `--border-subtle`、`--border-default`、`--border-strong`
- `--action-primary`、`--action-danger`
- `--status-success`、`--status-warning`、`--status-error`、`--status-info`
- `--content-chat-max`、`--content-settings-max`、`--terminal-agent-pane-width`

组件不得直接写十六进制颜色；只有令牌文件允许定义主题色。组件中的 fallback 在迁移完成后删除。

### 5.3 通用组件

建立以下基础组件，替代各页面重复拼装：

- `UiPageShell`：页头、内容宽度、滚动和页级状态。
- `UiPageHeader`：eyebrow、标题、说明和唯一主动作。
- `UiSection`：区块标题、说明、次动作和内容槽位。
- `UiFormGrid`：一列、两列、整行字段的统一栅格。
- `UiActionBar`：仅在脏状态出现的保存 / 放弃操作条。
- `UiDataList`：MCP、Linux 通道、模型、Agent、Trigger 的一致列表。
- `UiEmptyState`：标题、原因、下一步和可选主动作。
- `UiStatusBadge`：统一 ready、running、offline、error、disabled。
- `UiIconButton`：统一尺寸、Tooltip、焦点和 aria。

`SettingsPageHeader` 应升级为 `UiPageHeader` 并覆盖 Agent 详情；`ConfigPanelShell` 不再决定页面级保存布局。

## 6. 核心页面目标布局

### 6.1 Agent 对话页

输入栏及其下方按钮位置保持不变。重点是统一内容轴、消息宽度和稳定状态区。

```text
┌──────── 248 ────────┬──────────────────── Agent 工作区 ────────────────────┐
│ Agent 列表           │ 页头：Agent 名称                         [消息][终端] │
│                      ├──────────────────────────────────────────────────────┤
│                      │                                                      │
│                      │        对话内容轴 860–960 px                         │
│                      │        Agent 文本 / 工具卡片同宽                      │
│                      │        用户消息右对齐、最大 440 px                    │
│                      │                                                      │
│                      ├──────────────────────────────────────────────────────┤
│                      │ 输入栏（位置不变，高度稳定）                           │
│                      │ MCP  终端  Skills                  深度思考 / 状态      │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

修改要点：

- 工具卡片、文件引用和 Agent 正文共享同一内容轴，不再出现“工具比消息更宽”的视觉断裂。
- 瞬时状态占固定槽位；待审批数量只在输入区提示一次。
- MCP、终端和 Skills 的弹层使用同一宽度、标题结构、空状态和列表行高。
- Skills 的“全”不使用强蓝色徽标抢占注意力，改为低对比文本或 Tooltip 中说明。

### 6.2 终端工作台

终端是主任务面，Agent 是辅助上下文；会话切换应横向放在终端区域顶部，避免再增加左侧栏重量。

```text
┌──────── 248 ────────┬──────────────────── 终端工作台 ─────────────────────┐
│ Agent 列表           │ [local-1 ●] [wsl-1]                         [+][收起] │
│                      ├───────────────────────────────┬──────────────────────┤
│                      │                               │ Agent 消息            │
│                      │ Terminal                      │ 宽 380–520，可拖拽      │
│                      │ 主工作区                       │ 可收起，保留未读/审批提示 │
│                      │                               │                      │
│                      ├───────────────────────────────┴──────────────────────┤
│                      │ 发给「通用助手」…                 模型 / 发送 / 停止   │
│                      │ MCP  终端  Skills                  固定状态槽位          │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

修改要点：

- Agent 面板默认 420 px，可在 360–520 px 间拖拽，宽度持久化；关闭后终端立即占满。
- 输入栏继续位于底部，但必须显示发送对象，例如“发给通用助手”，避免与 Terminal 自身键盘输入混淆。
- 当前 Terminal 输入焦点、Agent 输入焦点使用不同焦点环和提示。
- 无终端时空状态提供唯一主动作“新建终端”，而不是只告诉用户去寻找右上角 `+`。
- 会话名称、连接状态和关闭操作放在横向标签中；不要再增加第三条左侧会话栏。

### 6.3 设置页

```text
┌──── 设置导航 220 ────┬─────────────────────────────────────────────────────┐
│ ← 返回对话           │ 页面标题                                  [主动作] │
│ 设置                 │ 一句话说明 / 范围标签                                │
│                      ├─────────────────────────────────────────────────────┤
│ 工作区               │ 区块标题                                             │
│ 工具与运行           │ 两列表单或紧凑数据列表                                │
│ 智能体与自动化        │                                                      │
│ 系统                 │ 区块标题                                             │
│                      │ ...                                                   │
│                      │                  [有修改时才出现的粘性操作条]           │
└──────────────────────┴─────────────────────────────────────────────────────┘
```

设置主区不再是一整张大卡片。导航与内容直接落在应用背景上，内容区用分隔线和语义区块组织。页面标题、范围说明和主动作保持相同位置。

## 7. 逐页修改清单

| 页面 | 当前问题 | 目标修改 | 优先级 |
| --- | --- | --- | --- |
| Agent 对话 | 状态出现时输入区增高；资源徽标注意力过强 | 固定状态槽位；统一三个资源弹层；保持现有位置 | P0 |
| 终端工作台 | 主次关系弱、空态浪费、Agent 面板过窄、输入对象不明 | 横向会话标签；可拖拽 Agent 面板；明确“发给 Agent”；空态直接新建 | P1 |
| Workgroup | 关闭时直达路由仍显示不可执行引导 | 路由守卫、隐藏入口、轻提示后返回 Agent | P0 |
| 通用 | Node ID 和底层信息占据默认页；运行状态卡价值低 | 默认只展示名称、日志和健康摘要；ID 移入诊断并提供复制 | P1 |
| 模型与连接 | 模型行操作碎、上下移动和删除缺少层级 | 统一数据列表；默认模型用状态标签；行操作进 `…`；新增为页头主动作 | P1 |
| MCP | 高级 JSON 入口过于突出；状态中英混用 | 新增服务为主动作；高级 JSON 进次级菜单；统一中文状态和工具数 | P1 |
| Linux 通道 | 凭据和通道同页但关系弱，ID 噪声大 | 使用“凭据 / 通道”两个紧凑区块；默认隐藏内部 ID；测试结果行内反馈 | P1 |
| 能力 | 配额字段平铺，用户难理解生效范围 | 先显示功能开关，再显示“运行配额 / 子 Agent”分组；单位放入控件后缀 | P2 |
| Skills | 全局页依赖当前 Agent，仍表达已加载状态 | 改为技能目录与发现状态；Agent 可见范围移入 Agent 详情；说明快照更新时机 | P0 |
| Agent 列表 | 模板和实例层级近似，卡片信息不足 | 实例优先；模板折叠为次级区域；显示模型、能力摘要和状态 | P2 |
| Agent 详情 | 单页过长、多套保存动作、页头不统一 | 拆为 5 个页签；统一页头；每页签一个保存边界 | P1 |
| 定时任务 | 空态同时出现页头“新建”和卡片内“新建” | 只保留一个主动作；空态说明触发频率、目标 Agent 和下一步 | P2 |
| 输出防护 | 技术字段可用但缺少风险解释 | 添加推荐范围、单位后缀和恢复默认；危险值即时校验 | P2 |
| 上下文 | 数字字段多、术语密集、诊断入口抢层级 | 按“压缩 / 时间注入 / 工具结果”分组；高级诊断折叠；显示推荐值 | P1 |
| 关于 | 命令帮助三列密度不均，中英文混排 | 版本卡置顶；快捷键用两列；命令改为可搜索折叠列表；技术上传命令进高级区 | P2 |

## 8. 状态与交互规则

### 8.1 加载

- 首次加载超过 150 ms 才显示骨架，避免闪烁。
- 骨架必须保持最终布局尺寸，禁止内容加载后整体跳动。
- 超过 8 秒显示错误说明和“重试”，不无限显示“加载中”。

### 8.2 空状态

空状态必须回答三个问题：这里是什么、为什么为空、下一步能做什么。只有确实可执行时才展示主按钮。关闭能力导致的空状态要解释如何启用，但不要暴露不存在的入口。

### 8.3 保存

- 页面加载完成后建立表单快照；仅当值发生变化时显示操作条。
- 保存成功用轻量 Toast，并立即刷新快照；不在页面中永久占一行“保存成功”。
- 离开脏表单前确认；重新加载必须说明会丢弃未保存修改。
- Agent 配置中的“保存”和“应用到运行态”如果是同一事务，只保留“保存并应用”；如果不是，必须拆成清晰的两步状态。

### 8.4 状态色

状态不能只靠颜色表达，必须同时有文字或图标。成功色只用于成功，蓝色只用于可交互或信息，禁止用蓝色装饰无动作的普通字段标题。

### 8.5 破坏性操作

删除模型、凭据、MCP、Linux 通道、Agent 或 Trigger 时，确认框必须显示对象名称和影响范围。默认按钮不是删除；批量或不可恢复操作要求输入名称确认。

## 9. 文案与范围表达

页面标题下统一增加范围标签，但不重复堆文字：

- `全局`：影响 Node 上所有 Agent，例如 MCP 服务目录、Linux 通道目录。
- `Agent`：只影响当前 Agent，例如工具权限、可见 Skills、绑定通道。
- `会话`：只影响当前会话，例如 Thinking、当前终端、上下文诊断。

用户默认只看中文产品语言。内部 ID、原始枚举、API 路径和 JSON 放入“高级 / 诊断”。允许保留的英文包括 MCP、Agent、Skills、Linux、Token 等产品术语，但同一页面不得混用 `ready` 与“已就绪”、`Health` 与“健康状态”。

## 10. 前端结构调整

### 10.1 样式拆分

将 `workbench.css` 按职责拆分：

```text
styles/
  tokens.css
  base.css
  layout/
    app-shell.css
    chat.css
    settings.css
    terminal.css
  components/
    buttons.css
    forms.css
    lists.css
    overlays.css
    states.css
  pages/
    agent-detail.css
    about.css
```

迁移阶段允许旧样式存在，但新增组件只能使用新令牌和基础组件。每完成一个页面就删除对应旧规则，禁止以 `overrides.css` 长期覆盖。

### 10.2 状态模型

为所有设置页统一：

```ts
type PageState = "loading" | "ready" | "saving" | "success" | "error";

interface EditablePageState<T> {
  value: T;
  snapshot: T;
  dirty: boolean;
  state: PageState;
  error?: string;
}
```

列表页统一 `loading / empty / ready / error`，避免每个页面自己决定占位方式。

### 10.3 视觉回归

为以下页面建立固定截图：

- Agent：空会话、有消息、工具展开、待审批、生成中、取消中。
- 终端：无会话、单会话、双会话、Agent 面板展开 / 收起。
- 设置：通用、模型、MCP、Skills、Agent 详情、上下文、关于。
- 主题：浅色 / 深色。
- 尺寸：1366 × 768、1600 × 900、1920 × 1080。

## 12. 产品级验收标准

满足以下条件后，才认为本轮 UI 重构闭环：

- 运行状态变化不会改变输入栏、消息区或终端区几何尺寸。
- Workgroup 关闭时没有入口、没有可直达半成品页面。
- 所有设置页只有一个明确主动作，且页头、区块和保存反馈一致。
- 1366 × 768 首屏可看到页面标题、关键状态和主动作，不需要先滚动。
- Agent 详情每个配置域有独立导航和清晰保存边界。
- Terminal 会话可直接切换，Agent 面板可调整且不阻碍终端主任务。
- Skills 页面与“快照重建 + 变更事件 + 按需查询”的真实机制一致。
- 浅色 / 深色主题所有文本、边框、状态和焦点均可辨识。
- 关键操作可用键盘完成，图标按钮都有 Tooltip、aria 和焦点环。
- 组件不新增硬编码颜色；字号、圆角和间距只使用批准令牌。
- 视觉回归覆盖第 10.3 节的页面、状态、主题和尺寸。

## 13. 明确不做

- 不为手机重新设计导航和布局。
- 不通过增加更多卡片、渐变、阴影或动画制造“高级感”。
- 不新增活动页、监控大盘或首页来掩盖现有层级问题。
- 不在输入栏资源面板中加入配置、重试、删除等管理操作。
- 不把全局资源和 Agent 绑定重新混在同一个入口中。
- 不在本轮改版中改变 Turn、审批、终端和 Skills 的后端业务契约；UI 只准确表达现有机制。
