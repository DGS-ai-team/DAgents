# 文件系统经验手册

日期：2026-09-09。状态：实现中，替代实验性 SQLite 手册设计。依据：用户要求指定目录，由模型自主创建层级、修改文件，不引入数据库。

## 产品行为

智能体设置提供手册根目录，留空使用 Agent 私有默认目录。目录配置由用户管理，模型在已配置的目录内组织文件，无须先提交数据库候选或等待单篇手册激活。文件是内容的唯一事实来源，用户使用外部编辑器修改后，后续文件读取应可见。

不强制固定目录结构。README.md 可作为入口，但不存在时允许从目录列表开始。界面提供目录路径、层级浏览、文件内容和修改记录；手册不再表现为一个大文本字段加数据库版本下拉框。

模型按需浏览、读取、创建目录和修改文件。已经发送给模型的请求内容保持不变；后续工具读取可以读到自己刚写入或用户更新的内容，不能用整轮冻结机制阻止这一行为。目录索引和读取内容有大小限制，不在每轮将整个目录塞入上下文。

## 存储与执行边界

- 根目录由可信 Agent 配置解析，工具只接受相对路径；默认目录按 Agent 分离，同工作目录不自动共享手册。
- 路径校验覆盖上级跳转、绝对路径、链接和 Windows junction；失败时不降级为任意文件访问。
- 修改前校验内容摘要，冲突提示重新读取；单文件写入采用临时文件与替换，失败不留下半篇正文。
- 历史与恢复信息使用文件保存；内部历史目录不作为普通手册内容暴露给模型。恢复产生新修改记录。
- 事实记忆继续复用现有 memory 存储。去除新代码中的手册数据库初始化与运行时依赖，不删除用户现有数据库或自动导出历史实验数据。
- 手册是经验资料，不能改变岗位职责上限、工具权限、预算或核心指令。文件操作仍经过既有执行策略和用量链路。

## 必须取得的验收证据

1. 真实 Agent 工具调用创建多级目录、写文件、读取、修改；磁盘内容与工具返回一致，不靠直接调用存储 helper 代替。
2. 同一会话写后读可见新内容；已构造请求不会被外部文件变化静默改写。
3. 两个默认配置 Agent 相互隔离；越界路径和链接逃逸失败，目录内正常层级可操作。
4. 外部编辑后新读取可见；旧摘要写入发生冲突，不能覆盖用户修改。
5. 服务重启后内容和文件历史可读，恢复旧内容保留之后发生过的修改记录。
6. 设置目录、文件树和内容通过真实 HTTP/UI 验收，切换 Agent 时旧请求不能覆盖新页面。
7. 每日维护和普通聊天都能在各自授权内使用手册；使用已配置 LLM 做真实创建与改写测试，记录磁盘证据及用量。

本文件记录验收要求，不代表上述能力已完成。整体阶段仍按 Auto 数字员工实施方案验收。

## 2026-09-09 实现进度与剩余接线

已提交文件存储与中断恢复（be2a20a2）、绑定手册目录的文件工具和历史（352a2b19）、Auto 运行时目录索引与入口读取（6080fa3f）、目录配置和浏览/恢复接口与设置页（2ab55c84）。独立复验通过 handbookfs、agentruntime、turn 包测试；这些证据不替代真实模型和浏览器验收。

现有每日维护的 `MaintenanceRunner` 只负责事实记忆抽取，尚未调用带文件工具的手册整理轮次。内部 `Manager.RunHandbookMaintenance` 已随 a99ce517 提交，接受实际持有的 Agent 维护租约，复用工具策略执行多轮文件操作，区分修改、缺失用量与等待交互。定向测试包含多级写入/读取/替换、取消、租约隔离和中间模型请求缺失用量；这些使用脚本化 LLM 客户端，不属于真实服务商验收。

接下来由生产控制器在同一 Agent 维护执行锁内增加手册阶段，使用该 Agent 的 LLM 配置及受限文件工具，允许模型自主组织层级。手动运行和定时运行应共用控制器，分别报告事实记忆与手册结果；前一阶段成功、后一阶段失败属于部分完成，不能声称跨数据库与文件系统原子提交。

手册阶段需独立持久化执行凭据、预留维护额度并记录真实用量；中断后不能仅凭模型请求结束就推断文件修改完成。工具访问范围须在执行层限制到手册目录，不能只依赖提示词。现有文件工具提供可选摘要校验；自动整理已有文件时必须携带读取所得摘要，缺失或冲突的处理仍需执行器验收。

尚待取得：每日维护真实工具轮次、已配置 LLM 创建和改写磁盘文件、同会话写后读与恢复上下文、更新后 Node 界面桌面/移动视觉验收，以及手册阶段的预算不足、取消、重启和外部修改冲突证据。

### 生产控制器复核补充

工作区中的手动入口与调度入口已接入共享手册控制器，但尚未验收或提交。手动 HTTP 测试使用脚本化客户端，能够写入默认手册目录并记录维护用量；这不能证明自定义目录、定时执行、持久审计或真实 LLM 全部通过。

复核发现，按 `maintenance-` 会话名前缀跳过维护输出会误伤正常业务输入，现有 `maintenance-scheduler` 回归已暴露该问题。增加数字后缀匹配仍不足以确认来源。最终实现必须使用持久化的维护执行记录与会话 ID 关联，保留维护审计并防止将维护输出递归作为业务经验；不能依据用户可构造的名称判断。

提交生产控制器前还需验证：同一定时 occurrence 不重复执行手册阶段；自定义目录真实文件写入；零余额在调用前拒绝；调用前失败不产生虚假的未知用量；运行时随维护租约有序释放；维护结果与执行记录可关联查询。无文件能力时应明确呈现手册未执行及原因，不能仅用记忆阶段通过证明整次手册维护完成。

### 增量证据与中断恢复

`7b781866` 提供从实际处理输入生成的有界维护证据，`eaeda68c` 修复维护轮次的输入消息持久化，`0418d805` 按可信执行凭据过滤维护输出并跨页读取业务记录。工作区控制器的独立维护竞态回归已通过，包含业务原文进入模型请求、无增量跳过、指定目录写入和取消清理；均使用脚本化客户端，不代表真实 LLM 验收。

复核发现：事实记忆提交会推进业务游标，而手册证据目前仅由函数返回。若随后进程中断，重启会越过尚未整理的业务证据。因此必须在推进游标之前，将有界证据与记忆候选、下一游标一起写入现有维护执行凭据；旧候选恢复接口不得清除已经保存的证据。该记录是恢复所需的输入证据，不是手册内容存储。

手册执行使用与来源凭据关联的稳定标识。尚未调用模型的待执行状态可恢复；已经开始模型调用而结果未确认的状态须进入待核对，不能在重启后自动重复执行。手册结果与实际用量必须持久化后才能把整个维护标为完成。手动与定时入口共用此规则，不能仅凭记忆游标已推进或当前无新输入推断手册阶段成功。
