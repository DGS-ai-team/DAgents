# Auto Agent 产品模型调整

依据用户 2026-09-08 的纠正：长期任务不是普通 Agent 上的一项独立功能，而是自主 Agent（Auto Agent）的运行能力。本文件取代早期 P1 文档关于入口和 Agent 类型的产品假设；实现验收另行记录。

## 产品入口与交互

- Agent 分为普通 Agent 与自主 Agent，历史 Agent 缺省为普通类型，不自动迁移或启用任务。
- 创建和智能体基本设置明确显示类型。自主 Agent 的智能体设置提供“自主任务”入口，每个自主 Agent 对应一份任务配置。
- 自主任务配置采用一项一行：左侧名称与说明，右侧控件；目标和完成条件等长文本允许更高行，窄屏自然换行。
- 自主 Agent 空闲时使用原有主聊天，具有普通 Agent 的模型、工具和对话能力。聊天页提供自主类型、任务状态和任务设置入口。
- 用户可以在主聊天要求修改目标、完成条件和下次唤醒，或暂停任务。模型通过实际工具保存配置，不能仅在回复中声称已修改。
- 原长期任务页面保留执行记录和专用执行会话入口，不再作为普通 Agent 创建自主任务的主要路径。

## 执行边界

复用已有 Goal、Trigger、专用执行会话和预算核算。自动执行与普通聊天属于同一个 Agent；主聊天忙碌时推迟自动唤醒。专用执行会话保留运行证据与审批，不能通过普通消息绕过自动执行计数。

新建自主 Agent 未配置时不调度。用户在设置中显式启用任务。聊天调整只作用于当前 Agent 自己的配置，不允许提高用户设置的次数、预算或频率上限，不重置已用次数和 Token。完成、停止、预算耗尽或结果未知的任务不能被模型自行复活。执行中的目标修改需等待本轮结束，避免改变当前执行的验收依据。

类型转换需要 Agent 空闲；转回普通类型前先暂停任务，并确认没有执行中或结果未知的运行。历史任务保留，不根据列表顺序把旧任务自动绑定为自主任务。

## 验收门槛

1. 创建两类 Agent，刷新后类型和设置入口保持一致。
2. 自主 Agent 配置保存后存在明确绑定、执行会话和调度器；停用后不会继续唤醒。
3. 自主 Agent 空闲时真实模型聊天正常；通过聊天修改任务后，设置页读回实际变更。
4. 后续受限运行采用新目标，运行历史与用量继续累计。
5. 普通 Agent 不获得自主任务管理工具；自主 Agent 不能修改其他 Agent 或提高限制。
6. 旧任务记录、原有聊天、反馈入口及一行一项设置布局回归正常。

## 本轮验收结果

真实模型主聊天、对话修改意图、设置页读回、调度自动唤醒新目标和证据完成均通过，见 [前端真实验收记录](2026-09-08-frontend-live-acceptance.md)。前端 59 个文件、323 项测试通过；Go goals、triggers、api、tools、agentruntime 测试通过，最终类型切换保护另经 API 测试验证。

本轮仍保留终态不可重新启用的限制：已完成或停止的任务不能在原 Agent 中开启新一轮任务，目前需要创建新的自主 Agent。后续应设计显式任务周期切换，保存旧周期历史与预算记录，避免复用 Agent 必须丢失身份的问题。
