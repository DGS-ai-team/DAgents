## 1. 优先级与交付边界

本轮 P0 为自主长期任务与反馈功能提供执行和身份前提。P1 先交付 Node → 当前 Manage 的反馈闭环，再交付单 Node 长期目标。完整顺序见 [Roadmap](../roadmap.md)。

| 编号 | 问题 | 本轮交付 | 发布门槛 |
|---|---|---|---|
| P0-M | 缺省配置授予匿名 admin；默认密码；Node ID 可直接换取会话 | 默认拒绝未认证请求，显式管理员凭据、可信 Node 登录和 WS 身份绑定 | HTTP/WS 匿名、冒充和旧 cookie 均不能绕过；合法配置可继续使用 |
| P0-T | Trigger 目标字段未参与实际运行时选择；条件命令直接执行宿主 shell | 按已有 Agent 解析运行时并校验归属；拒绝任意 shell 门控 | Agent A/B 的模型、工具、策略和工作目录不串用；所有 fire 入口遵守门控限制 |
| P0-D | pending 检查/入队/标记分离，且 pending 不持久化 | 稳定投递身份、原子领取、持久化保护和恢复核对 | 并发与故障窗口没有无法解释的重复派发；失败不会伪装成完成 |
| P0-U | 启动错误无恢复入口；Trigger UI 不可选择实际目标，也未接 fire/history | 启动重试与帮助；目标选择、立即运行、投递历史 | 正常/失败/重试/刷新状态可理解，已有布局和首配边界不回退 |

## 2. Manage 身份契约

1. 未配置 API token 不代表匿名获得管理员身份；保护接口必须认证。
2. 管理员密码通过现有部署配置显式提供；未配置时登录拒绝，Console 解释配置要求。本轮不增加网页密码创建流程。
3. Node ID 是身份标识，不是凭据。Node 登录必须提供绑定该 Node 的认证证明，或由已认证管理员显式访问。
4. Workgroup WS 验证凭据，并将 header/hello 声明的 Node 身份与认证结果对应；A 的凭据不能冒充 B。
5. 保留显式配置的管理员、共享 token 和 Node token 的既定合法使用路径；通过版本化 cookie 淘汰弱默认产生的旧会话。现有会话保存在进程内存，服务重启后重新登录；本轮不另建持久会话存储。
6. token 不进入 URL；测试只使用测试凭据。Node→Manage 连接依然由 Node 主动发起。
7. 新增响应字段、登录参数与行为变化同步文档和机器契约；UI 必须能解释缺少配置及无效凭据。

## 3. Trigger 执行与投递契约

### 3.1 Agent 归属

用户选择 Node 上已有 Agent，实际派发复用该 Agent 运行时。不得只保存一个显示字段而继续使用 Node 默认模型/工具。已有会话必须校验归属；未知或已删除目标不能回退到另一个 Agent。

P0 新建 UI 只开放目标 Agent 的主会话（`fixed`）。已有非固定模式保留原值并解释限制；尚未实现安全归属的模式必须由后端明确拒绝，不能静默切换到默认运行时。独立长期任务会话在 P1 按 Goal/Run 契约建设。

兼容旧默认 node_id 任务时明确记录旧语义，不隐式创建新 Agent。Agent 的工具创建触发器仍绑定自身，不能通过参数逃逸到其他 Agent 权限。

### 3.2 任意命令门控

本轮收紧 `condition.cmd`：新建/更新非空任意 shell 条件返回可理解错误；既有任务保留原数据，但自动、手动与 force 入口均不能执行该命令，也不能通过跳过 gate 而继续执行后续任务。历史明确说明原因。

未来需要条件检查时，应通过有限条件或已有受控执行接口建设，本轮不另造一个 shell policy 引擎。

### 3.3 并发与恢复

- 先持久化领取记录，再执行投递；落盘失败不得进入执行入口。
- 调度时刻、人工请求与投递身份的关联必须清晰。同一未决投递不能重复入队。
- 消费确认携带投递身份，迟到的旧确认不能清除新投递。
- 正常消费后的下一次触发必须可用；内存与磁盘不能保留两套不同步的 pending 标记。调度扫描使用旧快照时，同一到期时刻也不能在前一次快速消费后再次派发。
- 多个存储之间没有事务时不得声称 exactly-once；在关键窗口崩溃后先核实输入与生命周期事实。
- P0 允许采用保守恢复：无法确认时标为需要核对并暂停相关 Trigger。该状态必须在 API/UI 可见，提供显式恢复说明或动作。
- 恢复规则同时检查旧 InputBox 内容，不能仅暂停计时器而让未决旧消息偷偷执行。
- 人工恢复按 `delivery_id` 核对，只放弃旧投递且保持禁用；即使先恢复 Trigger、后加载 Agent，旧输入也不得重新执行。恢复记录应保留可追溯身份和原因。
- 已落地的 InputBox FIFO、HITL 等待和 Turn cancel 语义继续保留。
- `queued` 只表示已投递；触发历史不是长期目标完成记录。本轮不增加平行的工具状态机。

## 4. UI 验收契约

1. 首次连接失败显示原因概述、可禁用的重试按钮和独立于后端的帮助；详情可查看/复制。不得在重试期间重复发起无限请求。
2. 重试成功能进入首配或应用；晚到的旧请求不能覆盖新结果；不能通过软重检绕过首配。
3. 新建 Trigger 明确显示目标 Agent，不能只有不可编辑的默认目标；API 返回错误后保留用户输入。
4. 立即运行提供明确投递结果；历史按权威状态区分已投递、跳过、失败、需核对。
5. 保留 [现有 UI 约束](ui-product-grade-redesign.md)：对话输入位置、终端 Agent 面板、Workgroup 关闭态和主题令牌。不存在可用后端时也能理解当前失败及下一步。

## 6. 验收记录（2026-09-08）

P0 实现通过当前范围验收，尚未发布。编码由 Luna 完成，主负责人进行了代码审查、故障用例返工和独立复跑。

- Manage：默认关闭匿名访问、无默认密码、Node token 与身份绑定、旧 cookie 名失效；注册归属在 Store 锁内核对。Python 全量 181 项通过，Ruff、Pyright 通过。
- Trigger：所选 Agent 冷加载使用其自身模型快照；禁止跨 Agent 会话误投递；停止 shell 条件执行；持久化投递身份、同步确认、旧调度时刻重复领取、恢复身份和 HTTP enable/force 限制均有回归验证。
- InputBox：执行前与完成后的 SQLite 故障注入通过；故障时保留输入并停止消费者；未决记录不能被下一条输入覆盖。人工恢复后，即使随后加载旧输入，原先有效的活动 Turn continuation 也会被拒绝。无投递身份的旧输入恢复时不自动执行。
- 独立检查：`go test ./node/...`、`go vet ./node/...` 通过；此前其他 Go 模块的 test/vet 通过。Node Web UI 52 个测试文件、304 项通过；Node 和 Manage 两套前端构建通过；API/Workgroup 契约与 OpenAPI 路由检查、`git diff --check` 通过。
- 浏览器：Node 启动失败详情、复制与重试，Trigger 目标、立即运行结果、历史与需核对状态通过隔离 Mock 检查；Manage 管理员登录/错误密码/退出、Node 回车登录、有发现分组和无分组状态通过隔离真实 Manage 检查。

验收边界：浏览器原生确认框受自动化工具超时影响，未将“点击确认后恢复成功”计作浏览器通过；实际恢复成功、错误身份拒绝、恢复后保持禁用已通过 HTTP 测试。Node UI Mock 不证明真实 LLM 长期执行能力。持久化异常需修复存储后重启并核对；本轮采用保守暂停与人工恢复，不承诺 exactly-once。
