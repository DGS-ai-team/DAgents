# P1：反馈闭环与单 Node 长期任务

状态：P1 单 Node MVP 已验收，未发布。主负责人制定范围并独立验收，Luna 编写实现和测试。继承 [P0](p0-controlled-execution-foundation.md) 的投递、身份与恢复约束。操作入口见[使用说明](../user/long-term-tasks-and-feedback.md)。下方阶段记录保留实施过程中发现的问题，以末尾最终记录为准。类型与入口以 [Auto Agent 产品模型](2026-09-08-auto-agent-product-model.md) 为准，取代下方早期普通 Agent 创建 Goal 的方案。

## 1. 交付顺序与边界

先交付 Node → 当前 Manage 的反馈，再交付单 Node 长期任务和任务界面。两条后端链路可独立开发，UI 随契约接入。保持原有聊天输入、终端及工作组布局。此阶段不建设跨 Node Goal 调度、附件反馈、多用户 Node 隔离或新的通用工作流引擎。

## 2. 反馈契约

用户主动填写类型、标题、正文；不自动附带日志、对话、文件或凭据。Node 本地持久化后显示“已保存，等待发送”，只有 Manage 持久化确认后显示送达。未配置 Manage 可保留草稿，但不能静默绑定后来配置的管理方并发送。

每条记录保存稳定客户端 ID、创建时的 Node 身份与 Manage 目的地。投递复用 Node 出站认证 HTTP；禁止自动跟随重定向把反馈或凭据送往其他主机。地址或身份范围变化后旧记录阻止发送，显式呈现原目的地。不得把 token 存在反馈记录或返回浏览器。

Manage 按认证身份与客户端 ID 幂等入库；正文的 node_id 不能授权。Node 只能读自己的反馈；管理员才能读全部、筛选、修改处理状态和回复。状态为 open/in_progress/resolved/closed，处理采用 revision 并发校验。反馈重试不能覆盖管理员状态或回复，重复 ID 内容冲突不能静默篡改原文。限制长度、分页和提交速率，正文与回复按纯文本呈现。

Node 主动同步处理状态。请求失败不丢正文，重复同步不重复提醒；换 Manage 不自动迁移旧反馈。Manage 关闭或 Node 离线不能影响正常聊天。

## 3. 长期任务契约

Goal 记录目标、可观察完成条件、所属 Agent、专用会话、授权限额、状态、最近进度和下次唤醒。Run 保存稳定身份、计划时刻、对应输入/Turn、开始结束事实、用量与结果。复用现有 Trigger 调度和 InputBox/Turn 执行链；不能用 queued 表示运行成功或目标完成。

每个目标使用所属 Agent 的真实模型、工具和 policy 快照，不能回落默认 Agent。长期任务专用会话与主聊天分开，但共享工作目录不构成隔离。单 Goal 最多一个排队或活动 Run；同 Agent 忙碌或审批等待时合并/延后唤醒，不抢占人工活动。

用户创建时设置最大运行次数、累计 token 限额、截止时间和最低唤醒间隔；每轮同时设置步骤、工具次数、token 与时长上限。模型可以减少执行或在范围内安排后续唤醒，不能扩大预算、频率或权限。预算用实际 Turn 用量累计；无用量数据不能当作零，无可用费率不展示零成本。执行入口和工具入口均受约束，不能另建普通 Trigger 逃逸限额。

受控 checkpoint 工具只能操作调用会话当前活动 Goal/Run，保存摘要、证据/产物、下一步和后续时间；不可由调用参数指定其他目标。完成声明必须具备证据，且对应 Turn 已成功收尾、无未决审批或副作用，才进入完成状态。失败或未知结果不能因一次工具调用宣称完成而被覆盖。没有有效进度或完成记录时不得无限续跑；连续无进展应暂停并解释。

暂停只阻止后续运行，当前运行可收尾；停止同时调用既有 Turn cancel，旧回调不能恢复目标。等待审批展示可直达既有会话的入口。重启时未决 Run 保守标记待核对并暂停，不自动重放；闲置期间错过的唤醒最多合并为一次。人工核对不等于无条件重试副作用。

通知默认仅用于完成、审批等待、阻塞、预算耗尽或实质异常；无变化检查保留历史，重复状态不重复提醒。用户能看到依据、当前等待原因、剩余预算及下一步操作。

## 4. UI 与验收

Node 提供本机反馈入口与详情；Manage 管理菜单提供用户反馈列表、筛选、回复和可刷新定位。创建失败保留草稿，区分送达状态与处理状态。

当前 Agent 工作区提供长期任务入口、三类模板（持续观察、分批完成、条件跟进）、创建表单、详情和 Run 时间线。显示目标、完成条件、下次唤醒、进度证据、预算、暂停/停止及会话入口。原有审批卡片继续作为权威操作入口。

验收必须覆盖：

- 反馈在线、离线重启、丢响应重试幂等、并发 revision、跨 Node/匿名拒绝、切换 Manage、管理员回复回到 Node。
- Goal 真实 Agent 冷加载、并发唤醒合并、真实 Turn 关联、停止迟到回调、审批等待、累计预算、无进展暂停、重启待核对、工具越权拒绝。
- SQLite/投递故障不能被显示为成功；测试需实际走 HTTP、生命周期和故障窗口，不能仅检查字段存在。
- 有限真实模型验证仅在临时工作目录操作合成文件，覆盖三类目标及失败/取消；记录实际调用和产物，不以 Mock 结果替代真实模型验收。
- 按改动运行 Go/Python/Vitest、两套 UI 构建与契约检查，浏览器检查表单、刷新、错误和操作闭环。未通过的项目明确保留为未完成。

### 最终验收记录

- 反馈闭环：隔离 Node 提交、Manage 管理员回复并解决、Node 同步显示已送达与原回复；刷新详情保留身份和记录。权限、幂等、丢响应重试、目的地绑定与限速有 HTTP/存储回归。
- 调度：负责人复跑同 Agent 主会话忙碌时手动 409、定时不消耗 Run、空闲后运行；同 Agent 两个 Goal 并发仅一个启动，不同 Agent 可以并行。Trigger 下次时间窄更新的持久化失败回滚与投递状态保留通过。
- 恢复与审批：冷重启按原 Agent 重建专用 runtime，归档 Agent 不回落默认；hydrate 不替换活动 Turn。审批 HTTP 回归确认批准前文件不存在、批准后实际写出 `ok`、Run 成功结算。普通消息不能绕过 Goal 唤醒直接启动运行。
- 浏览器：专用会话 404 已修复；暂停目标重启后历史可读，返回主聊天不混入 Goal 记录；停止后隐藏运行操作，仍可查看专用历史；普通发送禁用，保留审批用途说明。
- 检查：Node 全量 Go 测试、Node vet、Python 全量 185 项、Node Vitest 58 文件 317 项、两套 UI 构建、API/Workgroup 契约检查通过。新增审批文件执行断言另独立复跑通过。

验收边界：真实模型验证覆盖三类合成文件目标；并发、取消/迟到回调、故障及审批恢复主要使用确定性模型测试。未进行数天连续运行、跨 Node 调度或新增 browser/terminal 外部故障演练；不据此承诺任意工具场景均可靠。Node 需保持运行，未知执行不自动重放，Token 阈值不是精确费用硬上限。临时复制的模型凭据已清理，原运行配置未修改。
