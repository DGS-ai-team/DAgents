# Desktop 资源页自动刷新方案

日期：2026-10-18。状态：**实现已接入，自动回归及本轮核心能力原生窗口验收完成**。适用于当前 Desktop + Node 个人工作台，不改变资源访问权限、终端生命周期和聊天上下文。具体证据与覆盖范围见[本轮记录](audits/2026-10-18/resource-refresh-and-inline-previews.md)。

## 1. 目标与现状

用户在资源页查看文件、图片、终端和浏览器时，应能看到 Agent 或外部程序造成的变化，无需反复关闭、重新打开。自动刷新不打断输入，不覆盖未保存内容，不重置资源页的位置。

制定方案时的代码基线如下，具体实施状态以上述验收记录为准：

| 资源 | 当前实现 | 本轮需要补齐 |
| --- | --- | --- |
| 工作区目录、文本、图片 | 打开时读取；手动刷新目录会清空当前文件选择；没有自动检查 | 增加静默目录更新和文件版本检查，分离导航与刷新 |
| 终端 | WebSocket 接收输出及退出状态 | 保留实时流；补齐会话列表的变化同步和恢复时检查 |
| 浏览器 | 可见时每 3 秒读取查看器画面 | 返回页面保留原页面选择；断线保留最后画面；未启动状态可自动恢复 |

推荐采用 **事件提示失效 + 可见页面定时检查**。首轮不引入递归文件监听、独立事件服务或全局刷新开关。定时检查覆盖外部编辑器、脚本、终端写文件，以及未声明文件路径的工具；仅依赖工具结果无法覆盖这些来源。

## 2. 调度与职责

Node 负责资源的真实状态、鉴权、工作区边界和内容版本；Desktop 负责是否可见、何时检查，以及安全地更新展示。文件检查始终由本机 Node 完成，不使用 Desktop 本地文件监听。

| 场景 | 建议行为 |
| --- | --- |
| 首次打开资源 | 立即读取，显示首次加载状态 |
| 文件页可见 | 当前目录每 3 秒检查一次；仅检查当前目录与打开文件，不扫描子目录树 |
| 打开文件内容 | 目录中的大小/修改时间变化时立即校验；另以 10 秒为周期做强版本校验，超过 1 MiB 的文件改为 30 秒 |
| 工具完成 / 当前 Agent 一轮结束 | 合并 300ms 内的通知，对可见文件页安排一次检查；不以工具成功或失败判断是否写过文件 |
| Desktop 上传、保存成功 | 更新本地已知版本，再安排一次目录检查，合并重复通知 |
| 页面隐藏、进入设置、窗口最小化 | 停止文件与浏览器轮询；终端已有流保持连接 |
| 返回资源页、窗口恢复、Node 重连 | 立即检查一次，恢复正常调度 |
| 临时网络错误 | 保留最后成功内容，重试间隔依次为 5、10、30 秒；成功后恢复正常周期 |
| 切换 Agent / Node / 工作区、关闭资源 | 取消旧调度并废弃旧响应；即使取消网络请求失败，也不允许结果写入新页面 |

以上周期为首轮默认值，不新增用户配置项。轮询使用上次请求完成后的 `setTimeout`，不使用可能重叠的 `setInterval`。同一资源最多一个刷新请求；请求期间收到多个通知，只保留一次待刷新标记。设置有限请求超时，不能因为一次挂起而永久停刷。

刷新归属至少包含连接代次、Agent、工作区代次、资源路径/会话 ID。切换归属后增加代次；不能只比较路径。内容区域完成原有切换动画后再启动目标页轮询，避免隐藏页面抢占读取和界面更新。

## 3. 文件更新规则

### 3.1 目录

新增独立的静默检查路径，禁止复用当前会清空文件的 `loadDirectory()` 导航行为。按路径比较目录项，仅更新发生变化的行；保留当前文件、目录滚动位置、排序和焦点。目录项新增、删除、重命名自然反映；不自动跳转到新文件。

当前列表已提供大小和纳秒格式修改时间，可作为检查提示；这些信息不是强版本。不能因为大小、时间相同就永久跳过内容校验。

### 3.2 文本和图片

| 状态 | 检测到 Node 文件变化后的行为 |
| --- | --- |
| 没有本地编辑 | 更新内容和 ETag；保留文本滚动、光标和选择，超出新内容时裁剪到有效位置 |
| 有未保存编辑/本地草稿 | 保留全文、草稿及原始保存 ETag；显示“文件在外部已更新”，不弹窗、不自动合并、不改变保存基线 |
| 正在保存 | 合并并延后应用刷新结果；保存结束后重新校验；旧读取结果不能覆盖刚保存的内容 |
| 读取期间用户开始编辑 | 以应用结果时的编辑代次再次判断；不能按请求开始时的“无编辑”覆盖后来输入 |
| 文件删除/重命名 | 目录移除旧条目，打开的内容保留，并提示“文件已不存在”；禁止自动创建、重建或覆盖 |
| 图片变化 | 新数据成功解码后再替换画面，随后释放旧 Blob URL，避免空白闪烁 |
| 文件被替换成不支持的类型/超限 | 保留最后可读内容并提示状态，停止尝试渲染；不把原缓冲误当最新版本 |

保存仍使用强 ETag + `If-Match`；外部改动导致 412 时保留草稿。外部最新版本与本地编辑基线分别记录，不能把后台读取到的新 ETag 填给旧草稿，从而绕过冲突保护。

冲突提示只提供“重新载入”和“另存本地副本”等恢复动作；丢弃草稿重载必须经用户确认。不在本轮加入自动合并或强制覆盖。

对原子替换文件产生的短暂 404 先做一次延迟复查；权限拒绝、路径越界等错误不能伪装成删除，也不能高频重试。所选文件确定删除后可随目录检查确认是否重新出现，重新出现时仍遵循草稿保护。

手动“刷新”也改用上述保留状态的检查；切换目录、主动打开另一文件仍走原有离开草稿确认。刷新不显示整页骨架、不重建编辑控件、不改变资源页签名称。

### 3.3 最小 API 调整

复用现有 `GET /v1/agents/{agent_id}/workspace?path=...` 和 `GET .../workspace/file?path=...`，不新增 watch/stat 路由。

- 文件 GET 支持 `If-None-Match`：内容强 ETag 一致返回 304、无正文；变化返回 200、正文及新 ETag。按 HTTP 条件请求语义解析，而非简单字符串相等。
- Desktop 二进制传输已可转发 `If-None-Match`；客户端需将 304 表示为 `notModified`，不能当作错误或空文件。
- Node 仍需读取并计算内容摘要才能确定强 ETag。304 节省传输与渲染，不承诺消除磁盘读取开销；仅校验当前文件并降低大文件频率控制成本。
- 首轮目录仍返回现有 JSON，由客户端比较条目；不为降低少量 JSON 传输增加目录 ETag 或服务端缓存。
- 保留现有路径规范、`.dagents` 隔离、符号链接/目录联接防逃逸、文件大小限制，以及 PUT 的 `If-Match` 约束。

## 4. 终端与浏览器

终端输出继续使用现有 WebSocket。定时“刷新”不能清屏、重新执行命令、重开终端或重置滚动。关闭展示页仍仅分离展示，终止会话仍使用明确的终止操作。

会话选择窗口打开时拉取最新列表；接入 Node 已有的 `terminal.updated` / `terminal.closed` 通知后，仅使该 Agent 的会话元信息失效并合并更新。实现时先核对这些通知的事件封装与 Desktop 转发链路，不假定当前已消费。流异常时显示断开，用户明确重连或按现有可靠恢复协议恢复，不能静默重复创建会话。

浏览器保留 3 秒查看器画面更新，仅当前可见页面轮询。这里的刷新是重新获取截图/页面信息，**不是浏览器 `reload()`**，不打断 Agent 的导航、表单和登录状态。423 忙碌时保留旧画面，稍后重试；503/网络异常按退避处理。未启动时降低到 30 秒检查，或收到相关工具完成通知后立即检查；禁用状态等待能力变化或用户重试，不一直请求。切回页面时保留仍存在的页面 ID，仅实际关闭后选择有效页面。

## 5. UI 表现与范围

正常检查静默完成，不增加常驻状态栏、彩色状态点或刷新动画。首次加载保留加载反馈；短暂网络问题保留内容，持续异常显示一条低干扰状态提示，恢复后自动消失。外部编辑冲突/删除在当前文件区域提示，不能混进发送消息错误。

本轮仅更新资源页。聊天历史中的内联图片不随轮询改写：不能为了文件页刷新而重新读取所有历史消息图片。资源链接点击时仍重新校验当前资源；未来若要求可复现的历史附件，需要独立的快照存储方案。

## 6. 实施顺序与验收

1. Node 条件读取 + Desktop 304 契约，保留保存冲突语义。
2. 文件页拆分导航/静默刷新，补可见性、请求合并、草稿保护和异步归属。
3. Desktop 资源事件失效接入，浏览器恢复策略和终端会话元信息同步。
4. 在真实 Tauri 窗口、真实 Node 文件与终端上验收；不需要调用付费 LLM来验证磁盘刷新。

涉及代码：`desktop/ui/components/WorkspaceFiles.vue`、`desktop/ui/workspace-files-api.js`、`desktop/ui/DesktopApp.vue`、`desktop/ui/components/BrowserViewer.vue`、`node/internal/api/workspace_api.go`，必要时调整 Tauri 二进制响应处理及对应测试。逻辑抽取仅用于复用请求调度和可测试的状态判断，不建立新的全局资源管理框架。

- [ ] 外部新增/删除文件在目录检查后出现；无需关闭资源页，选中文件与滚动不丢失。
- [ ] 文本、PNG 等被外部改写后自动更新；同大小同修改时间的改动也能在强校验后发现。
- [ ] 输入、保存与读取交错时不丢字；412 保留草稿，后台刷新不绕过保存冲突。
- [ ] 304 不清空内容、不触发图片解码和整页重绘；删除、恢复和超限表现明确。
- [ ] 快速切换资源、Agent、Node，旧响应均不能写入新页面；隐藏页面停止轮询。
- [ ] 断网保留内容，退避重试；恢复/回到窗口立即校验；不产生重叠请求或工具事件请求风暴。
- [ ] 终端持续输出，不因页面刷新丢输出、清屏、重连或创建新终端。
- [ ] 浏览器查看器更新画面，不重载真实网页；忙碌、尚未启动和短暂掉线后能按规则恢复。
- [ ] 中文/空格/百分号文件名、目录联接越界与私有目录限制保持原有行为。
- [ ] 大文件和多个已挂载但隐藏的资源不产生无界轮询；记录可见时请求数量及恢复行为。
