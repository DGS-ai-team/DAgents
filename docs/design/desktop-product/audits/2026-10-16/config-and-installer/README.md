本轮继续 PR #346 的交付收束。Luna 编码，主线程检查范围、代码和验收证据；未重新运行此前被自动审批拒绝的安装循环、Browser 服务启动或 Desktop 重开。

## MCP 配置页

上轮 API 改为显式返回 `enabled_tools` 后，工具开关 PATCH 只更新服务列表、没有同步编辑器文本。用户再点击“保存并刷新”，旧 JSON 就会覆盖刚保存的工具开关。本轮修复这个往返问题，并补齐同一流程中的失败分支：

- 首次读取成功前禁止编辑或保存，不再填入可直接提交的示例服务，避免慢请求或读取失败时覆盖已有配置。
- 加载、保存、刷新目录和工具 PATCH 互斥；不在后台重读整页并覆盖用户草稿。
- 工具 PATCH 成功只合并对应服务的 `enabled_tools`，保留其它服务和用户新输入的凭据；失败保留草稿并回滚复选框状态。复选框失败后留在错误状态的问题曾在组件测试中实际复现，修复后通过。
- 编辑器 JSON 无效或该服务已从草稿移除时，不发送工具 PATCH。

四项组件回归覆盖首读失败、挂起读取/写入互斥、配置草稿与工具开关共存、无效/已移除服务，以及 PATCH 失败后的文本和 DOM 状态。Node Vue 全量 414 项、共享图标 6 项、Desktop UI 51 项测试通过，两端 Vite 构建通过。这些是组件与构建结果，不是本轮原生窗口验收。

Desktop 本机设置与 Node 业务设置的存储及路由另经源码核查：`/settings/desktop` 通过 Tauri 本机设置命令访问，Node 未首配时仍可进入；本轮没有为这部分新增无必要的重构或运行时。

## 安装器生命周期归属

安装器直接执行 Shell 生命周期命令，虽然指定了当前 `config.yaml`，但没有覆盖继承的 `DAGENTS_HOME`。Rust 以 home 确定安装根和 Desktop 单实例标识，因此环境指向另一安装时，“退出 Desktop”可能发送给另一份程序。

`RunShellCommand` 现在在执行前临时把 `DAGENTS_HOME` 和 `DAGENTS_CONFIG` 绑定到当前安装目录；生产 Desktop 配置使用当前用户默认路径，QA 继续使用当前安装下的独立 JSON。所有设置和执行都在 `try/finally` 内，最后逐项尝试恢复继承值；设置、执行或恢复失败则返回错误，终止升级/卸载流程。没有改变 Rust 通用路径规则或新增 CLI。

品牌资产与源码契约检查通过；本机没有 ISCC，未进行本地 Inno 编译。新增 Windows CI 的编译契约覆盖 x64/x86、生产/QA 四个分支，复用现有 assembler 和 installer build 脚本，使用合成二进制及真实 runtime 种子，不发布或运行生成的安装包。最终编译状态以 PR 对应 head 的 CI 为准。
