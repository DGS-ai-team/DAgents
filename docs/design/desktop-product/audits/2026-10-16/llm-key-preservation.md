# LLM 配置编辑丢失密钥修复

日期：2026-10-16。

## 根因与复现

用户确认在已有配置中点击过“测试/获取模型”。编辑弹窗在模型探测或选择后，无条件将配置 ID 改为模型名称；父面板只用 `original_id` 查找本地条目，未把来源传给 Node。Node 按 ID 保留加密密钥，整个配置列表替换后，新 ID 没有密钥，旧 ID 被移除。

主线程在独立 Node `127.0.0.1:18976` 使用合成配置验证旧版本：创建后 `has_api_key=true`；同 ID 修改模型后仍为 true；模拟自动改 ID 且省略密钥后变为 false。API 响应未泄漏合成密钥。测试结束恢复原配置列表，全部原配置的密钥存在标记与测试前相同；未读取、输出或改写真实密钥。

## 修复

- 编辑已有配置时，探测和模型选择不自动改配置 ID；新建时继续提供模型名称建议。
- 用户主动改名时，前端保留并发送只写 `original_id`，同时保持 Node active 配置选择。来源元数据在保存成功后由公开视图重新加载而清除。
- Node 在无新密钥且未明确清空时，从原配置迁移密钥。缺少来源、来源仍存在于最终列表、多个目标共用来源、目标已被占用等歧义会失败，不改变 LLM 配置库。
- 密钥仅在 Node 进程内解密和重新加密，GET/PATCH 视图仍只提供 `has_api_key`，不提供明文或改名来源字段。
- 保存失败后再次打开编辑，会用当前本地 ID 定位条目，模型探测继续使用原存储 ID，避免二次保存提示配置不存在。

## 验证

- 前端完整测试：82 个文件、451 项通过；共享图标 6 项通过。
- Go `internal/api` 全包通过；`internal/setup`、`internal/store`、`internal/agentruntime`、`internal/llm` 通过。
- 合成密钥回归覆盖：同 ID 编辑、改名、批量保存、明确清空、替换、歧义拒绝且库不变、只写字段不回传。
- 完整 HTTP PATCH 回归使用真实临时加密 store，验证改名后响应标记和 active 正确、新 ID 可解出原合成密钥；再次明确清空后响应标记与存储均为空。
- Vue 挂载测试实际点击探测和确认，覆盖保持配置 ID，以及保存失败、重开、再次探测与改名保存。
- Node 与内嵌前端的原生 Desktop 均构建成功；本轮新构建尚未重启到真实原生窗口复验，不将此前终端 UI 验收算作本功能的原生证据。

需同时更新 Node 和 Desktop。已经被旧版本清空的密钥不会自动恢复。本轮不迁移各 Agent 对手动改名前配置 ID 的绑定；该既存限制记录于 Node 接入契约，编辑时探测不再自动改 ID 已避免本次触发路径。
