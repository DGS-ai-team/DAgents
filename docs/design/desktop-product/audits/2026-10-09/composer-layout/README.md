# Desktop 输入栏布局评估

日期：2026-10-09。范围：真实 Tauri 窗口的普通智能体对话输入栏；仅评估，不修改产品代码。

## 1. 默认输入状态 — 需要调整

证据：[真实窗口截图](01-current.jpg)。当前从左至右为 `default`、附件、消息输入、发送。

合理之处：单行高度约 58px，发送按钮位于右端，黑灰色控件与整体风格协调；底部没有额外常驻状态栏。

问题与建议：

- 模型配置放在最前面，让低频配置先于高频输入占据阅读起点。建议改为「附件 → 消息输入 → 模型选择 → 发送」，保持文字输入起点稳定。
- 当前 `default` 实际为 LLM 配置名，而非实际模型名。`ComposerToolbar.vue` 优先使用 `active_profile`，完整 provider/model 放在悬停提示。建议优先显示简短模型名称，配置名在选择菜单中解释；同时保留实际配置区分，避免多个同模型配置难以辨认。
- 模型选择应使用中性、小尺寸文本，无独立醒目背景，限制宽度并截断，悬停展示完整信息，避免长名称挤压输入区。
- `desktop-ui.css` 将 textarea 的高度、最小高度、最大高度都固定为 40px，外框固定 58px。换行只能在很小区域内滚动。建议短消息保持一行；多行时自适应增高至约 4–6 行，达到上限再滚动。展开后正文在上、附件和模型及发送在下，避免永久增加一条工具栏。

## 验收边界

已直接观察真实窗口空输入状态，并核对模板和样式。当前配置只有一个 mock/default 配置，模型切换控件不可操作；没有修改 LLM 配置、发送消息或验证多模型下拉交互。多行问题依据当前固定高度样式判断，未输入草稿。

## 推荐优先级

先调整模型位置与显示内容，再改多行自适应。保留现有黑灰配色、简约发送按钮及紧凑的默认高度。

## 落地与复验

用户批准方案后，由 Luna 实现，主审复核真实 Tauri 窗口与代码。

1. 空输入状态 — 通过。附件在左，模型在发送按钮前；显示实际 `mock` 模型，悬停提示为 `mock / mock · 配置: default`。空文本保持约 56px 单行输入框。原配置名展示仍为共享 Web UI 组件的默认行为。
2. 三行草稿 — 通过。正文在上方展开，附件在下方左侧，模型和发送在下方右侧，输入起点保持一致。[截图](03-multiline.jpg)。修复了发送箭头受全局图标颜色覆盖而与背景接近的问题。
3. 八行草稿 — 通过。正文展示约六行，其余在输入区域内滚动，外框没有继续增长。[截图](04-six-line-limit.jpg)。
4. 切换智能体 — 部分验证。三行草稿从自主助手切到普通助手后，普通助手空输入框恢复紧凑高度。原有草稿归属与失败恢复测试均通过；未完成切回后草稿恢复的视觉操作。
5. 软换行与页面往返 — 代码复核通过，视觉操作未完成。展开判断使用紧凑布局的稳定输入宽度，避免展开后变宽导致反复折叠；窗口/侧栏宽度、文本、智能体变化和对话页重新挂载均重新测量，最多六行。

检查结果：Desktop 现有 UI 测试 34/34 通过，生产前端构建成功，修改文件的 diff whitespace 检查通过。构建仍有既有大分块和动态导入提示。

复验边界：只有一个 mock 配置，没有实际多模型切换或 LLM 请求，也未上传附件。继续验收时，Computer Use 将窗口尺寸误报为 `width: 15, height: 15`，重新获取窗口绑定仍未恢复，故停止进一步 UI 输入。自主助手最后一次测试使用了三行未发送草稿；未通过工具清理该草稿。误捕的非产品截图已移除，不作为验收证据。
