## 验收发现与修正

1. 资源页紧凑消息卡使用默认 Markdown 标题尺寸，长代码与图片导致卡片横向溢出。已为 dock 渲染增加紧凑排版、容器宽度约束和代码块内横向滚动。
2. 紧凑消息卡没有接入代码复制处理。已将复制行为统一放入 ResourceMarkdown，移除 MessageBubble 的重复处理，并覆盖复制内容、反馈重置与卸载清理。
3. 资源链接失败使用全局发送错误状态，出现重复提示和无关的“重试”。已拆为独立、可关闭的资源提示，切换智能体或有效打开资源时清除。

上述三项修正均已通过修正版真实窗口复验：

- 紧凑消息卡标题与正文保持协调尺寸，图片适配卡片宽度，卡片整体没有横向滚动条；长代码仅在代码块内部横向滚动。
- 点击卡内“复制代码”，将剪贴板与已知 QA 代码文本作本地相等比较，结果为 true；未输出剪贴板原文。按钮随后恢复默认状态。
- 点击不存在的终端引用，只有独立资源提示，没有发送错误或 Node 重试按钮；点击“关闭”后提示消失。随后打开有效报告，文件面板和资源提示均恢复正常。
- 等待手动打开修正版期间，先前验收终端已失效。现有终端注册表设置 10 分钟空闲回收；因此使用 API 创建新的 `local-terminal-2` 并保持 detach，更新 QA 助手回显，再从修正版消息卡成功恢复为已连接、只读。注册表总数保持为 1，未输入命令。
- 最终保持新 Node 和修正版 Desktop 运行。测试使用隔离 Mock 智能体和真实 Node 资源传输，不扩展为真实 LLM 输出质量、多平台或长时间稳定性结论。
