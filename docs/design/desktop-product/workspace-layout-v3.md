# Desktop 工作区细化方案 v3

状态：可操作原型的下一轮设计基线；2026-09-24。此文档只定义 Desktop 呈现与模拟交互，不是 Node API 契约。v2 的对话/资源双工作状态继续保留。

## 本轮视觉判断

在 4174 原型中查看了文件资源页、展开的待审批状态卡、侧栏和顶栏。右下角卡片折叠后只传达状态，用户要发一句话却必须离开文件或终端；展开后又有较多描述文本，不能输入。终端资源页签已经标识“终端 1 · bash”，下方再放会话选择框会重复导航并占一整行。侧栏折叠按钮单独撑开顶部约 40px；底部 59px 的 Node/设置栏与顶栏的应用设置入口职责重叠。对话消息应向既有 Web UI 的用户左侧柔和气泡、助手无框正文靠拢，时间只做辅助信息。

## 资源页悬浮消息坞

- 右下角常驻一个轻量消息坞，宽约 360–420px（随窗口缩小），与资源边缘留 12–18px。收起态由一行 Agent 名称与状态、下一行单行输入和发送键组成；不再需要先展开才能输入。输入框按 Enter 发送、Shift+Enter 换行时可扩为两行。发送仍留在当前资源页，状态转“生成中”，可查看简短回复。
- 点击状态标题/展开图标打开上方浮层，展示最后的用户消息、助手消息/生成进度、最近工具与审批。待审批请求应醒目并可直接允许一次或拒绝。浮层顶部或底部提供“查看完整对话”。消息坞自身不复制完整对话流，不承担长文阅读。
- 同一时刻只存在一个当前 Agent 的消息坞。换 Agent 后草稿、状态、最近消息与审批按 Agent 隔离；资源内容和消息互不串线。待审批不阻止用户输入一条后续消息，但“待审批”优先于“生成中”作为主要状态显示。
- 悬浮坞会遮挡资源右下角，终端/文件内容需给最后一行留足滚动余量；在 800×700 下展开浮层不得超出视口。聚焦输入时，不因终端键盘快捷键抢走焦点。

## 导航与空间

- 终端会话与其他资源统一通过顶部页签切换。删除终端内的会话下拉框及其专用 50px 工具栏；终端清空/重连/关闭等低频操作放在资源页签行右侧菜单。`+` 提供新建终端、浏览器、文件。当前会话名称仍显示在页签中。
- 侧栏折叠/展开按钮移到单行应用顶栏，靠近 DAgents 菜单，使用表示面板开合的图标与明确提示；侧栏内容从顶部开始，不保留空的按钮行。折叠后分组图标与浮层选择行为不变。
- 顶栏 DAgents 菜单承载“设置”和 Node/外观等全局入口；侧栏底部只保留连接状态，压至约 38–42px。折叠态用状态点、tooltip/可访问名称表示 Node；避免重复的设置齿轮。
- 正文文字优先保证清晰，次要元信息再降一级，不通过过浅颜色制造层级。状态颜色必须同时有文字或图标，不只靠色点。

## 对话消息

对照 `desktop/tray-tauri/src/ui/components/MessageBubble.vue` 与 `desktop/tray-tauri/src/ui/styles/workbench.css`：用户消息左对齐、柔和浅底与小圆角差异；助手消息是同一阅读列的无边框正文；不添加头像、姓名栏或仿短信的左右对打。时间可放在每条消息下方，11–12px、低对比但仍可读，不和正文抢层级。审批卡继续在对话流内完整呈现。

## Desktop 图标资产

当前原型直接通过 `@shared-icons` 使用 `shared/icons/desktop/` canonical 图标；`shared/icons/desktop/manifest.json` 保留来源与许可记录，不再复制 SVG 到 `prototype/public/assets/icons/`。24×24 viewBox、`currentColor`、2px 圆端线条、统一光学大小；16px 检查必须可辨认。优先从此前验收过的 DAgents/Lucide 资产选用，只有确实缺少的 Desktop 操作语义才按同一笔画语言补绘，记录每个图标的来源、映射和许可。品牌雪花仍使用现有 PNG，不改造成功能 SVG。

[iconfont](https://www.iconfont.cn/) 可用于查找形态参考；其搜索结果跨多个作者和风格，不能直接混用成产品图标集。若今后选定某一完整系列替换现有基础集，应先统一许可、笔画、视图框和 16px 表现，再整体迁移。

## 验收条件

在对话、终端、浏览器、文件中实际切换；在资源页直接输入并发送消息、看到生成/回复和待审批；分别展开与收起侧栏；检查终端无重复会话下拉、设置只在顶栏、状态栏高度、各状态图标及文字对比。至少检查 800×700 与常见桌面宽度，最后跑构建和现有原型测试。
