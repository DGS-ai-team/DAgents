# Desktop 日常使用接入与验收

日期：2026-10-08。基于已有本机 Desktop MVP，目标是不依赖打开旧 Node WebUI 完成主要日常操作。以下勾选表示已接入，实际验证范围和限制分别记录在后文，不表示所有分支均已人工实测。

## 功能闭环

- [x] 首次配置在 Desktop 内完成；空 Node 可以创建第一个智能体。
- [x] 创建普通/自主智能体，可从模板开始，配置模型和工作目录；编辑与删除有明确入口与错误反馈。
- [x] 对话可以发送、停止、清空上下文和切换模型；实际模型与显示名称一致。
- [x] 附件可选择/拖入/粘贴，失败保留草稿；文件引用与图片在 Node 持久化后可重新加载。
- [x] 图片缩略图和灯箱通过认证的 Node 媒体通道展示，凭据不进入页面 URL。
- [x] 终端使用 xterm 完整渲染，支持键盘输入、多实例、尺寸变化、恢复和明确关闭。一次性 `bash_run` 与交互 PTY 分离；Desktop UI 与同一 Agent 的 `terminal_*` 工具共享终端会话 broker，跨 Agent 会话隔离。该共享行为属于既定设计，本轮不重构。
- [x] 文件可以浏览、打开、预览、编辑、上传和下载；文本保存检测外部修改冲突。
- [x] 工作组可以创建、配置成员与模型、发布/订阅、发送消息、管理消息队列和处理审批；Manage 未启用或离线时给出实际原因。
- [x] Auto 总览显示真实状态、待办、下次唤醒与 Dreaming，并可跳回对话或配置；后台智能体状态更新不依赖当前选中。
- [x] 浏览器资源沿用 Node 的 Agent 浏览器会话，提供真实页面截图和页面选择；本轮只读观看，不包含人工接管、点击操作或地址栏导航。

## 实现约束

Desktop 保持单一连接的本机 Node；远程连接、版本能力协商和三平台发行不属于本轮日常功能接入验收。Rust 持有 Node 认证，负责 JSON、二进制和终端传输。文件读写由 Node 完成，不能用 Desktop 本地文件读取代替 Node 资源接口。

文件接口按智能体的工作目录限制路径，检查相对路径、符号链接及 Windows 路径逃逸；上传、读取和写入有大小限制。不能把文件内容当成网页执行。图片与文件缓存、资源页签、草稿和会话必须按智能体隔离。

界面保留已确认的合并顶栏、黑灰强调、三组侧栏、展开子项缩进、选中态和图标资产。Auto 总览进入顶部菜单，不恢复侧栏总览按钮和搜索栏。对话与资源分别显示；页签仅用图标和实际名称，资源页保留消息坞和审批入口。消息、工具气泡和审批复用现有 WebUI 设计。

## 验收方式

1. 使用已有 Node API、Rust 和前端测试验证真实契约，重点覆盖新增文件权限、传输边界与状态隔离。
2. 构建 Desktop 与 Node，重启实际服务，使用 Computer Use 验收真实 Tauri 窗口；浏览器中的 Vite 预览不代替原生接线验收。
3. 使用专用测试智能体与工作目录验证创建、聊天、资源和保存，不修改用户日常智能体的上下文。Mock 回显只证明传输和展示，真实模型验证另行记录。
4. 记录未验收的外部依赖或能力，区分“已实现”“真实链路已验证”“仍未实现”。未通过前不宣布完整替代 WebUI。

## 本轮验收记录

### 实现边界

Rust 的健康检查、设置、附件与资源传输移到异步命令的阻塞任务中，避免网络等待阻塞窗口。二进制接口限制为 16 MiB，检查编码长度和解码后的长度。历史媒体仅接受当前智能体所属的 Node 媒体路径，UI 用 Blob URL 展示并回收缓存。

新增 Node 工作区接口由 `os.Root` 限制在当前智能体的工作目录，拒绝路径逃逸、私有命名空间和特殊文件；文本更新必须携带 ETag，首次创建使用 `If-None-Match: *`。草稿保存内容和原始版本，重新打开时不会用服务器的新版本覆盖草稿的旧基线，冲突需要明确选择重载。HTML/SVG 等源文件以文本显示，不能执行。接口说明见 [workspace-file-api.md](../../development/workspace-file-api.md)。

工作组沿用 Node→Manage 契约，支持返回的 `queued` 和真实 loop 状态，不假设发送即已执行。审批仅提交选中的请求，其余保持待处理。进入工作组后隐藏普通 Agent 资源，并禁用其停止、清空和删除操作，避免操作错误对象。

浏览器观看经过 Node Manager 的现有 Agent 会话，不另建浏览器。侧车读取使用现有会话锁，不生成新的工具 refs 或 observe 编号。工具忙时立即返回 busy，保留旧画面并重试；未启动/禁用时停止自动轮询。资源区已在原生窗口修正为全宽，未启动状态使用中性提示。

### 检查结果

- Desktop 状态、草稿、工作组请求隔离、工作区和媒体测试：22/22 通过。
- Rust `cargo fmt --check`、库测试：29/29 通过。
- Node `go test ./internal/api` 通过；浏览器 Manager/远程 Driver/API 定向测试通过。
- 共享前端工作组、浏览器及会话契约测试：18/18 通过。
- Python browser-service 协议测试：6/6 通过；实际 Chromium smoke 通过。
- Desktop Vite 构建和 `git diff --check` 通过。构建仍有既有动态/静态 import 与大 chunk 提示，性能分包尚未完成。

验收后已归档三位专用智能体，恢复原 Manage 和功能配置，停止临时 Manage/browser-service，并用最新代码重启本机 Node。现有智能体的消息上下文与模型配置没有改写。

最终恢复配置时发现并修复两处状态问题：列表刷新移除当前智能体时，现在通过统一选择流程切换并清空旧终端/消息状态；Manage 明确禁用时清空侧栏旧工作组。另修复“文件 → 新建终端”只切换画布却未创建实例的问题。这三项均已在原生窗口复验，归档当前验收智能体后正确回到另一位的对话，没有旧资源或错误残留。

### 后续范围

本机 Desktop 主要日常入口已接入。远程 Node、版本/能力协商、浏览器人工接管、Office/PDF 等丰富文件查看器、三平台安装签名和升级回滚仍需后续开发。工作组需要可用 Manage 与 supervisor 模型，浏览器需要 browser-service 且 Agent 已通过工具启动会话。

新增链路主要用 Mock 验证传输和显示，不替代真模型端到端验证。此前真模型聊天和工具审批见 [mvp-closeout.md](mvp-closeout.md)。自动激活、Dreaming、各类审批、断线恢复和长时间运行仍需完整场景回归。Desktop 仍复用仓库内 Node WebUI 组件源码；无需打开旧网页操作，但源码职责拆分与移除旧 UI 入口尚未完成。
