# DAgents Desktop v2 原型视觉与交互验收

检查日期：2026-09-24。检查对象：本目录的可操作原型；布局意图见 [工作区布局与交互方向 v2](../workspace-layout-v2.md)。本轮根据用户的新要求重排了工作区，因此旧版 [`current-desktop-mockup.png`](../visuals/current-desktop-mockup.png) 只作视觉语言参考，不能用像素一致性判断新布局。

实际在 Codex 内置浏览器检查了以下流程。各步均查看了页面截图和可访问结构；截图显示在本任务的浏览器检查记录中，当前工具没有提供可复用的本地截图导出路径。

| 步骤 | 观察与结果 |
| --- | --- |
| 1. 打开对话 | 对话是独立工作状态，不混在资源页签内；保留无头像的消息与底部输入。上方重复的智能体标题已移除。**通过。** |
| 2. 从对话打开终端 | `资源 · 3` 菜单列出已打开资源及新建操作。进入终端后，顶部有明确的“返回对话”，页签仅列资源；固定 237px 聊天底栏已移除。**通过。** |
| 3. 查看右下状态 | 收起时只有当前 Agent、待审批状态与数量；展开后显示最近消息、工具、Node 归属、命令、允许/拒绝和“查看完整对话”。待审批状态点使用警示色，信息不只靠颜色表达。**通过。** |
| 4. 模拟审批与返回 | 点击“允许一次”后，显示“已允许一次 / 等待 Agent 继续”，没有把授权误写成任务已完成；返回对话后仍能查看同一审批卡。**通过。** |
| 5. 浏览器与文件 | 浏览器地址栏、文件名/只读标识各占单行；旧版重复 URL 和重复文件标题已去除。演示内容明确标注未连接真实网站或工作区文件。**通过。** |
| 6. 侧栏收起与对象切换 | 展开态是三组对象；收起态是 64px 三组入口，点组图标可在浮层中选具体对象，底部设置和 Node 状态保留。换到代码助手再返回通用助手时，原有三个资源和审批仍在。**通过。** |
| 7. 窄窗口 | 在 800×700 CSS px 检查，页面滚动宽高分别为 800×700；展开状态卡位于 `(470,332)`，宽 320、高约 358，完整落在视口内。**通过。** |
| 8. 生成中与状态恢复 | 在代码助手对话发送消息，立即打开终端，右下状态卡显示“生成中”；模拟回复结束后恢复“空闲”。已有待审批的通用助手继续优先显示审批状态，不被生成状态覆盖。**通过。** |

视觉尺寸基线：单行应用菜单约 48px；展开侧栏约 238px、收起 64px；工作区导航 50px；资源工具栏 50px；资源状态卡收起高约 54px。相比旧稿，终端/浏览器/文件可用高度显著增加。图标从 `../visual-system/dagents-icons/` 中的 DAgents canonical 语义资产，品牌青蓝、Auto 靛紫和审批警示色遵循现有视觉方向。

验证：`npm run build` 成功；`npm run test:sites` 为 4/4。浏览器实际点击检查没有发现阻断上述流程的问题，最终原型标签页没有控制台警告或错误。

限制：此原型不连接真实 Node、LLM、终端、浏览器和文件 API。窗口按钮与部分全局菜单仍是展示交互。截图和可访问树只能支持当前视觉与基础语义结论；完整键盘导航、屏幕阅读器、跨平台 WebView、真实审批恢复及更多窗口尺寸仍需要产品实现阶段验证。状态卡的辅助文字在大屏上略显小，可在设计系统定稿时进一步统一文字层级。
