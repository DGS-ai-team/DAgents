DAgents / product design review视觉审计稿 · 2026-09-11

Node 与 Manage 的 UI，收敛成一套可持续的视觉语言

本稿基于当前可运行页面逐页观察，补齐图标清单，标出不协调的交互符号，并给出 Node、Manage 共同使用的色彩、密度、组件和页面骨架。它是下一轮实现的视觉验收基准。

设计判断

保留两个产品的角色差异，统一它们看得见的规则，让用户在 Node 与 Manage 之间切换时仍然认得出 DAgents。

共用骨架

同一套 icon 与状态语义

Lucide round 线性图标、18px 默认尺寸、1.8px 描边。成功、警告、危险和 Auto 状态使用固定色值，文字符号只作为内容字符出现。

保留角色

Node 轻、Manage 稳

Node 维持淡蓝画布与侧边栏，突出对话和即时操作；Manage 维持暖白工作台，突出列表、审核和跨 Node 汇总。

优先收口

先解决语义混淆，再装饰

优先替换旧的 ✦、✎、×、⌃、!、⌘、M，并把 Auto 总览入口统一为 ReceiptText；阴影、圆角和留白随后按 token 收敛。

逐页观察

当前环境页面均已打开检查。下面保留优点，同时指出会影响产品感的一致性问题。

Node 对话与运行时

  • 优点：浅蓝画布、侧边栏分组、底部状态区已经有清晰产品骨架，聊天输入区的层级也容易理解。
  • 问题：Auto 总览悬浮入口仍是旧 sparkle，和画板定稿的 ReceiptText 没有接上。
  • 问题：Auto 分组图标、重命名、删除、折叠、MCP、反馈提示仍存在字符图标，线条风格断裂。
  • 问题：聊天首页出现很长的旧验收文本，首次进入应提供干净的欢迎/空状态，避免把测试噪音当成产品内容。
  • 方向：设置页坚持“一配置一行”，工具能力与可见技能拆成两行；侧边栏底部仅保留品牌状态、主题、设置。

Manage 治理与汇总

  • 优点：暖白背景、横向顶栏、卡片与表格已经形成稳定工作台气质，列表页的筛选器位置统一。
  • 问题：首页模块、空状态、AskAI 与筛选器里的加号/杂项符号需要接入同一图标注册表。
  • 问题：Auto 员工、用户反馈、能力市场目前空数据时纵向留白偏大，表格 shell 可以保留列头与示例状态。
  • 方向：固定内容最大宽度，统一列表筛选条与表格行高；Auto 员工使用独立紫色状态，和 Node 的 Auto 标签呼应。

实施顺序

这份稿子可以直接作为下一轮 UI 改造的验收顺序。

01
建立 Icon registry

封装统一 Icon 组件，先覆盖 P0 字符图标；所有图标提供 aria-hidden 与 tooltip 入口。

02
修正 Node 侧关键入口

Auto 总览改用 ReceiptText；Auto Agent 用 Bot + Sparkles 角标；保留品牌 PNG，仅用于品牌位。

03
收敛布局 token

按一配置一行、列表筛选条、表格行高和 8px 网格调整 Node 设置与 Manage 空状态。

04
补一次真实数据视觉验收

Node 注册到 Manage 后，用至少一个普通 Agent、一个 Auto Agent、一个反馈和一个工作组复核状态色、截断和空/满状态。

设计范围：Node 与 Manage 的图标覆盖、颜色、密度和页面骨架审计。此稿只用于评审，未直接修改生产页面；生产图标迁移以 docs/design/dagents-icons/lucide/ 为来源。
