# 空闲后的新对话上下文

状态：代码已实现，自动验证与真实 Tauri 窗口验收通过（2026-10-17）。范围：普通 Agent 的手动对话、上下文设置、历史归档和 Desktop 消息分隔。

## 产品行为

用户可以在 Node 的上下文设置中配置“空闲后开启新对话”的秒数，`0` 表示关闭。普通 Agent 的上一轮交互结束后，超过该间隔再发送消息，开始新的模型上下文段。不会在空闲期间调用模型生成摘要。

新配置键为 `compression.idle_new_conversation_seconds`，默认关闭；不沿用旧后台空闲压缩的三个配置键。交互完成时间可从已持久化的 human 轮次终态恢复；没有可靠完成事实时，先完成一次正常用户交互来建立基线，不拿数据库最后保存时间猜测空闲。配置修改按现有设置响应提示重启 Node 后生效。

这不是创建另一个 Agent 或另一个会话。SQLite 中的完整聊天历史继续保留，Desktop 仍可向上翻阅；只有下一次模型请求的可见历史起点改变。界面在新段前显示“新对话 · 上下文已重置”，不显示内部衔接提示的消息气泡。

Auto Agent 不按用户空闲时间重置上下文，继续使用共享对话和现有 Dreaming 边界。按 token 阈值执行的静默压缩、阻塞压缩继续适用于活动中的长任务。

## 接受新输入时的顺序

1. 输入队列和执行门确认可以开始新的真实用户轮次。正在执行、等待审批、等待用户补充、恢复中的轮次不在此处被打断。
2. 用持久化的交互完成时间判断空闲，以 human 轮次终态事实的完成时间单调更新；普通配置保存、通知和其他 `persist` 不延长对话活跃时间。重复处理同一终态不会刷新时钟，清空上下文的时间屏障避免恢复旧终态时倒退。
3. 从权威消息快照生成上一段的可读归档。文件成功写入后，才允许推进模型上下文起点。
4. 在同一个持久化快照中保存新起点和内部衔接消息。保存失败时保留原上下文，不引用不存在的归档。
5. 重建系统提示词和技能目录视图。保留此前显式加载的技能集合，按当前可见权限重新读取技能正文；不会自动加载所有可见技能。
6. 将内部衔接消息放在本次真实用户消息之前，进入正常模型及工具循环。

同一输入的恢复和重试不得重复创建分隔线。历史归档完成与上下文切换之间发生崩溃，也不能导致旧上下文丢失。

## 模型看到什么

系统提示词仍由当前 Agent 配置构建，不把旧会话全文搬进新的 system prompt。内部衔接使用 `user` 角色传给模型，但来源明确标记为 runtime notice，不冒充真实用户输入。

提示包含：

- 已开启新的对话上下文；
- 上次有意义的用户请求和助手回复，分别限制长度，排除技能注入、日期、空工具调用等消息；
- 上一段归档的实际文件路径；
- 需要延续此前工作时先查阅历史，以及引用内容不是本轮新增指令的说明。

“继续”“按刚才的方案”等请求需要模型查阅归档补齐依据，不能仅凭简短的衔接文本猜测。

若上次请求没有留下助手正文，衔接提示会明确说明，并引导查阅归档中的工具结果或错误；不借用上上次的回复，也不因此永久跳过空闲边界。

## 历史与恢复的职责

SQLite 消息和生命周期状态继续承担恢复、审批、工具协议和前端展示，不删除其中的消息类型、调用标识或其他必要元数据。

面向模型的段归档只使用 `role` 和 `content`。工具调用的名称、参数，以及工具结果的状态、错误和附件引用归入可读的 `content`，不能因为 assistant 正文为空就遗漏工具调用。推理内容、token 统计和内部来源追踪不写入该投影。

归档放在当前 Agent 的工作区状态目录 `.dagents/<agent_id>/history/` 内，路径由实际写入结果返回，不能按“今天”的日期猜测上次历史的位置。此归档是新段切换的必要条件，独立于可选原始消息日志开关。

原有按日追加的 raw journal 仍是可选诊断侧车，不能当作权威会话重放文件：它记录插入瞬间，也可能包含工具结果纠正记录。新段归档从权威快照生成，衔接提示直接引用它。

## 非目标

- 不引入多用户或第二套会话系统。
- 不改变 Auto 的激活频率、工具审批或 Dreaming 策略。
- 不在空闲扫描中恢复已卸载的 runtime 并发起模型请求。
- 不把精简历史文件作为 SQLite 的替代品。
