# 配置项参考

配置加载：`shared/config/config.go`。示例：`packaging/agent-client/config.example.yaml`。

**查找顺序**：CLI `-config` → `DAGENTS_CONFIG` → `packaging/agent-client/config.yaml`

---

## 顶层

| 键 | 类型 | 说明 |
|----|------|------|
| `node_id` | string | 可选；缺省自动生成并写入 `.runtime/node/node_id`；旧 YAML `agent_id` 仅用于迁移 |
| `listen.host` | string | 默认 `127.0.0.1` |
| `listen.port` | int | 默认 `18765` |
| `local.endpoint` | string | Client 连接 URL（**仅 config.yaml**，Web UI 只读展示） |
| `runtime_root` | string | Node 运行目录，默认 `./.runtime`（固定，不可配置；不属于 Agent workspace） |

Web UI：**设置 › 通用**（runtime/agent）、**连接**、**上下文**、**安全**。

## llm

连接档案权威在 SQLite（`llm_configs.db`）/ Web UI「设置 › 连接 › LLM 配置」。Node YAML 中的 `llm` 仅作空库首次迁移种子（可选）。

| 键 | 说明 |
|----|------|
| `provider` | `openai` \| `deepseek` \| `qwen` \| `vllm` \| `glm` \| `minimax` \| `mimo`（迁移种子） |
| `base_url` | API 基址；留空用 provider 默认；GLM / MiniMax / MiMo 使用 OpenAI-compatible Chat Completions |
| `model` | 模型名 |
| `api_key_env` | 环境变量名，默认 `OPENAI_API_KEY` |
| `mock` | `true` 时不调真实 API |
| `thinking` | `enabled` \| `disabled`（deepseek/qwen/openai/glm/minimax/mimo） |
| `reasoning_effort` | thinking 强度 |

**`max_steps`**：Agent 级配置（`agents.config_snapshot_json` → `defaults.llm.max_steps`），新建 Agent / 模板决定；勿写在 Node `config.yaml`。

## manage

| 键 | 说明 |
|----|------|
| `enabled` | 是否连接 Manage |
| `url` | Manage 基址，如 `http://127.0.0.1:8020` |
| `node_token` | 可选鉴权 |
| `registration.base_url` | 上报给 Manage 的本 Node 可达地址 |
| `registration.interval_seconds` | 心跳间隔 |
| `registration.ttl_seconds` | Manage 侧 TTL |
| `registration.team` | Console 分组 |
| `workgroup.enabled` | 是否启用 Node → Manage 的 Workgroup Dialer；省略时随 `manage.enabled` 默认为 true |

`manage.a2a.*` 不是当前配置项，Node 不会读取或启动旧的 inbox/placement 路径；跨机协作请使用 `workgroup`。

## compression

| 键 | 说明 |
|----|------|
| `silent_trigger_tokens` | silent 压缩阈值 |

| `idle_auto_compress_seconds` | 无动作自动压缩（0 = 关闭） |

## memory

| 键 | 默认 | 说明 |
|----|----|----|
| `auto_extract` | `false` | 压缩完成前，将 frozen slice 异步交给候选提取器；会额外产生 LLM 调用 |
| `candidate_queue_size` | `16` | 每个 Agent 的候选后台队列上限；队列满时丢弃可选任务，不影响当前 Turn |
| `max_candidates` | `8` | 单个压缩片段最多保留的模型候选数 |
| `core_budget_tokens` | `2000` | 后台整理时 Core 记忆预算；超出条目降级为 Recall |

候选先写入 `pending/model_inference`，只有无确定性冲突时才提升为 Recall；冲突继续沿用 typed HITL，后台整理不会自动批准，也不会向 InputBox / MessageQueue 注入消息。

## tools

Node 级仅保留编码与 bash 压缩；工具组由各 Agent / 模板 `defaults.tools.enabled_groups` 配置。

| 键 | 说明 |
|----|------|
| `bash_output_encoding` | `bash_run` 输出解码 |
| `file_encoding` | FS 工具默认文件编码 |
| `bash_compress` | `bash_run` 输出清洗与预算；可用 `output_mode: head_tail` 保留长输出尾部 |

## wecom

| 键 | 说明 |
|----|------|
| `enabled` | 是否启用；默认 false |

| `webhook_key` | 仅 key；与 `webhook_url` 二选一 |

## Node 运行目录子目录（相对 runtime_root）

| 路径 | 用途 |
|------|------|
| `memory/sessions.db` | Node 控制面 SQLite（Agent/消息快照，按 `agent_id` 隔离） |
| `policy/` | 审批策略 |
| `skills/` | Skills 元数据与正文（不属于 Agent workspace） |
| `history/` | Node 旧版/兼容 journal 根；新 Agent 写入自己的 workspace `.dagents/<agent_id>/history/` |
| `triggers/` | Triggers |
| `data/` | Node 旧版临时目录（兼容保留；新安装不主动创建） |
| `prompt_context/` | soul / custom；旧 `user.md` 仅用于迁移，用户称呼改由 PreferredName 注入 |

Agent 的 `workspace_root` 在创建 Agent 时选择并保持不变。文件、bash、终端等工具的相对路径均以该 workspace 为基准；Agent 私有审计与侧车写入 `<workspace_root>/.dagents/<agent_id>/`，不要把 Node 控制面 `skills/`、`policy/` 等路径当作 workspace 相对路径。

## Agent Card

- 文件名固定：**`agent-card.json`**（工作目录，非 config 路径）
- Node 注册 Manage 时会根据 Node 设置与运行时工具列表自动组装并上报，不再依赖仓库中的示例文件。
