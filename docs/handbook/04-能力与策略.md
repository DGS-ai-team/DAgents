# 04 · 能力与策略

## 本章回答什么问题

读完本章，你应能：

- 理解工具 registry 如何注册、审批与执行  
- 配置 `.runtime/policy/` 与 Tool Before Hook  
- 使用 skills、triggers、临时子 Agent  
- 理解上下文压缩触发时机与 cache 对齐思路  
- 切换 LLM provider 与 thinking 模式

## 1. 内置工具总览

工具在 Node 启动时注册于 `tools.Registry`，Orchestrator 通过 OpenAI function schema 暴露给模型。

### 1.1 分类

| 类别 | 代表工具 | 路径 |
|------|----------|------|
| **Shell** | `bash_run` | `tools/bash_run_tool.go` |
| **文件系统** | `read_file`、`write_file`、`search_replace`、`grep_file`、`glob` | `tools/fs_*.go` |
| **Skills** | `load_skills` | `tools/` + `skills/` |
| **Triggers** | `create_trigger` 等 | `tools/` + `triggers/` |
| **子 Agent** | `create_temporary_agent` 等 | `childagent/` + `tools/` |
| **元工具** | `ask_user_information` | HITL 专用 |

**全量参考**（description、参数、审批规则）：[附录/内置工具参考](./附录/内置工具参考.md)。

### 1.2 执行路径

```text
processToolCalls (tool_router.go)
  → policy.DecideTool
  → auto: Registry.Execute / StartBackground
  → approval: PendingHITL
  → childagent 工具: childagent.Manager
```

### 1.3 工作区路径约束

- 根目录：固定 `./.runtime`（`fs_root`，不可配置）  
- 工具路径均相对工作区；禁止逃逸到工作区外  
- system prompt **不**暴露主机绝对路径  
- `bash_run`：可配置 GBK/UTF-8 解码；超时过长可降级后台 job  

> 工具边界靠工具组 + 审批策略；跨机靠独立 Node 或 Workgroup 成员工作区。

## 2. Policy 与审批

### 2.1 策略文件

**目录**：`{fs_root}/policy/`

| 文件 | 作用 |
|------|------|
| `tool.approval.txt` | 工具级 always / ask / deny |
| `shell/*.approval.txt` | bash 命令模式级 |

首次启动从 `packaging/runtime/policy/` 种子复制。

### 2.2 决策结果

| 结果 | 行为 |
|------|------|
| `auto` | 直接 Execute |
| `approval` | SSE `hitl_required`（`execute_tool` item） |
| `deny` | 拒绝并返回 tool error |
| `always` | 本次及后续同类自动（Web UI 可选 always 决策） |

**源码**：`node/internal/policy/`、`turn/tool_router.go`

### 2.3 Tool Before Hook

60 秒内**重复相同工具调用**时，Hook 可触发三选项审批（继续 / 拒绝 / 始终允许）。

**实现**：`node/internal/hooks/`。

## 3. Skills

| 概念 | 说明 |
|------|------|
| 目录 | `{fs_root}/skills/` 或配置 `skills.root` |
| 加载 | 模型调用 `load_skills` 后正文进入 session `loadedSkills` |
| Prompt | 已加载 skill **正文**写入 system prompt；默认可用目录元数据在 system prompt 尾部；实验模式可改由 `list_available_skills` 查询 |
| 上限 | `skills.max_in_prompt` |

`load_skills` 会立即更新会话状态和 hooks；正在进行的模型请求保持不变，但显式变更会在下一个模型 Step 创建新的 context segment，使 skill 正文立即可用。磁盘自动变化仍在下一次 human Turn 应用。工具结果会返回 `session_state_applied_boundary` 和 `model_context_applied_boundary`。

`defaults.skills.catalog_tool_mode=true` 仅改变 Skill 目录发现方式：查询工具只返回可见名称、目录名和 description，不读取正文、不修改 loaded 状态，也不触发 context refresh；随后仍需调用 `load_skills`，正文仍在下一个模型 Step 生效。该实验默认关闭。

**源码**：`node/internal/skills/`、`session` 的 `loadedSkills` 持久化。

## 4. Triggers

| 类型 | 说明 |
|------|------|
| `interval` | 固定间隔 |
| `fire_at` | 单次定时 |

- 触发时：`EnqueueTriggerMessage` 入队 synthetic user 消息  

工具与 HTTP API：`GET/POST /v1/triggers`（见 `node/internal/api/`）。

## 5. 临时子 Agent

父 session 通过 `create_temporary_agent` 创建**子 runtime**：

- 共用进程、端口、FS 根  
- `RestrictedRegistry` 工具白名单  
- SSE 经 `RelayHub` 挂到父 `session_id`  
- 不持久化 SQLite；空闲自动 `OnChildSettled`

**手册**：[02 §4.4](./02-Agent-Node-核心.md)；设计细节 `node/internal/childagent/`。

## 6. 上下文压缩

### 6.1 触发

| 模式 | 配置键 | 行为 |
|------|--------|------|
| **silent** | `compression.silent_trigger_tokens` | 后台摘要，不阻塞 user |
| **blocking** | `compression.blocking_trigger_tokens` | 同步摘要，阻塞 turn |

步前由 `runtime` 调用 `compression.MaybeHandle`（**仅父 session**）。

### 6.2 Cache 对齐（要点）

侧车摘要与主 turn **共用前缀**：`BuildSystemPrompt` + `tools.Definitions()` + messages 前缀；尾部追加 ephemeral 摘要指令。避免独立 `CompleteText` 导致 Prompt Cache 全 miss。

**源码**：`node/internal/compression/coordinator.go`、`session/runtime_turn.go`

## 7. LLM 适配

### 7.1 Provider

| provider | 说明 |
|----------|------|
| `openai` | OpenAI 兼容 |
| `deepseek` | 默认；支持 `reasoning_content` |
| `qwen` | DashScope compatible mode |
| `vllm` | 本地 vLLM |

配置：`config.yaml` → `llm.provider`、`base_url`、`model`、`api_key_env`；生产使用建议在 Web UI 中直接输入 API Key，由 Node 加密保存并即时更新运行时配置。

### 7.2 MessageAdapter

**路径**：`node/internal/llm/`

- 统一出站 message 序列化  
- `reasoning_content` / thinking 模式  
- 流式 cancel：`turn/cancel_partial.go` 保留部分 assistant 与合法 tool 序列  

### 7.3 Mock

`llm.mock: true`：无需 API Key，用于 CI 与本地结构联调。
