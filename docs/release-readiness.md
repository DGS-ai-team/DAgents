# 下一版发布收束清单

评估日期：2026-10-17。最近正式发布为 `v0.11.0`（2026-09-11）；当前源码版本仍为 `0.11.0`。本清单以当前代码、PR #347 和实际验收记录为依据，不把构建、Mock、原生窗口和正式安装验收混为一谈。

## 发布判断与范围

建议下一版定位为 **v0.12.0：独立 Desktop 与 Node API 收束版**，先冻结功能、生成候选包、完成下列验收，再进入正式发布。版本号是本次建议，尚未修改 `VERSION` 或创建标签。当前不宜直接发布稳定版，主要缺口是发行包和恢复链路的最终验收，以及少量尚未闭合的配置行为。

本版覆盖 Windows Desktop、本机 Node、通过用户自建 SSH 隧道访问自己的 Node，以及可选 Manage 协作。Node 不再提供 `/ui/`；多个 Desktop 共享同一使用者的 Node 事实，不引入多人账号与 runtime 隔离。远端文件、终端、浏览器属于 Node 所在机器。浏览器资源当前是 Node 会话的只读观看，不承诺人工接管或本地嵌入式浏览器。

Windows x64 是主要验收对象；当前发布矩阵还包含 x86，不能以交叉编译通过代替 x86 实机运行。如果要缩减矩阵，必须在发布前明确决策并同步工作流、安装页与更新选包规则。Linux 发布 Node/Client/Browser 服务包，不发布 Linux Desktop。

## P0：进入稳定版前必须关闭

以下是本次建议的发布门槛，不表示这些能力都尚未实现。每项以最终候选提交和实际包为准，记录环境、包哈希、步骤与结果；失败项修复后重测受影响链路。

- [ ] **最新提交的 CI、审查与集成。** PR #347 合入 `dev` 前，Go 测试/vet/staticcheck/race/漏洞扫描、Python、前端、Rust、Windows 双架构、Docker 和打包检查全部通过。首轮新上下文提交发现 `context_archive.go` 的 SA4004，已修复并增加跨日期归档冲突回归，本地全模块 staticcheck 通过；仍需等待最新 head 全绿，旧 head 的成功不能替代。合并后冻结一个候选提交。
- [ ] **最终包的标准用户初装、升级、卸载与恢复。** 在一次性 Windows 用户或 VM 中，用真实二进制跑初装→首配→使用→运行中升级→重开→卸载；覆盖中文/空格路径、快捷方式、可选自启的开/关状态及静默升级、非本安装 Node/另一安装不受影响。确认配置、LLM 密钥、Agent 历史/记忆、工作区、Desktop 偏好保留。补无 WebView2、不可写路径、文件占用失败和从备份恢复的演练。不得声称已有应用级事务回滚。操作见 [安装升级清单](../packaging/windows/install-upgrade-acceptance.md)。
- [ ] **v0.11.0 用户迁移。** 当前无协议 marker 的旧安装会安全拒绝原地覆盖；此前 QA 版本升级不等于旧正式版本迁移。用脱敏的旧发行数据验证推荐步骤，明确备份、停止旧进程、新 Desktop 入口、Node-only 的变化、旧 YAML 迁移、Agent/Auto/Trigger/模型与工作区恢复，以及失败时恢复原版本的方法。数据库加密材料必须随备份保留，不能只复制一个数据库文件。若采用备份后重装路线，文档与安装器提示必须一致。
- [ ] **LLM 与 MCP 配置往返。** 在最终原生窗口验证：不改 Key→测试/获取模型→保存→重新读取→真实请求成功；补测试失败、取消、替换 Key 和明确清空。MCP 切换工具后再保存编辑器，既有开关、凭据及草稿不能被旧 JSON 覆盖，失败须保留草稿。前者目前有组件/加密 store/HTTP 证据，后者有组件证据，不能据此勾选原生操作通过。
- [ ] **配置 ID 改名的 Agent 引用。** 当前 `original_id` 只迁移密钥，不迁移各 Agent 的模型绑定（见 [API 契约](api/node-integration.md)）。必须用已有绑定的 Agent 复现实际结果，并完成安全行为：本版优先考虑拒绝修改仍被引用的 ID 并说明原因；或实现完整、可恢复的引用迁移。不能仅因密钥还在就把改名视为闭环，也不能静默改用其他模型。
- [ ] **最终候选的任务恢复与 Auto 耐久。** 做一轮不少于 24 小时的持续运行，覆盖唤醒、无事可做、用户插话、Todo 修改、待审批、拒绝、停止、Dreaming、经验注入和手册文件。分别在运行/待审批/空闲状态重启 Desktop 或 Node，核对队列、历史、工具副作用和调度，不重复执行未知副作用；工具无工具收尾、失败批次及空闲上下文边界一并做候选包冒烟。既有各专项证据保留，不要求重复全部测试矩阵。
- [ ] **实际 SSH 与发行服务。** Windows Desktop 经用户创建的 SSH loopback 隧道连接现代 Linux Node，验证掉线/重连、远端文件上传下载/冲突、终端恢复与明确结束，确认不会启动本机 Node。实际运行打包 Browser 与 Chromium，查看页面并执行一次浏览器任务；缺失依赖时明确降级。对仍发布的 x86 和 Linux 包做基础启动、配置和主要服务冒烟。`--help`、源码运行和安装器占位编译均不替代此项。
- [ ] **版本资料、依赖审计与发布产物。** 汇总 `v0.11.0` 以来全部产品变动；当前 `Unreleased` 仅记录新上下文，尚不足以作为本版 Release Notes。更新 README/操作手册/路线图中的 Desktop、Node API-only、配置归属、浏览器只读观看、支持平台与升级说明，替换过时的主要界面图。用 `prepare_release.py` 统一版本，再运行 `validate_release.py`；当前校验仅证明 `0.11.0` 元数据一致。核对真实发布构建的文件版本、包内容、许可证、SHA256SUMS、release-manifest 和更新选包/下载后安装链路。

## 不作为本版前置条件

浏览器人工接管与可交互嵌入式页签、Desktop 自建 SSH 隧道、LAN/WAN 直连鉴权、多用户/租户隔离、macOS/Linux Desktop、新事件总线/工作流系统，以及再次全面重写 UI/runtime，均留到后续独立立项。当前个人 Node + 外部 SSH 转发的边界不变。

## 执行顺序

1. 修复 PR #347 的 CI、完成审查并合入 `dev`；冻结新增功能。
2. 关闭配置 ID 引用行为，形成迁移说明；生成带真实应用二进制的候选包。
3. 先完成标准用户初装/旧版迁移/升级恢复，再完成原生配置与资源冒烟；耐久测试可同时进行。
4. 关闭上述验收发现的问题，重建候选并只重测受影响链路；补齐版本资料与最终依赖审计。
5. 按 [发布流程](release-process.md) 建立 `dev → main` 发布 PR，通过检查和审查后，在 `main` 对应提交打标签；发布后校验实际资产、安装与升级，再同步 `main → dev`。

本轮只提交开发 PR 和评估清单，不创建发布标签，不把未验证项目标为完成。
