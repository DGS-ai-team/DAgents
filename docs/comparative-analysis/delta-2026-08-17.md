## 3. OpenAI Codex

### 3.1 执行环境统一

Codex 将 `unified_exec` 默认扩展到 Windows，并让 Windows 使用统一的 `exec_command`/`write_stdin` 能力，而不是另一套 `shell_command` 暴露方式。[相关提交](https://github.com/openai/codex/commit/d8d7ca73f80e992cade867970ceb264431cea33c)

这说明 Codex 正在把“执行命令”收敛为跨平台统一协议，而不是让上层 Agent 直接感知平台命令差异。

对 DAgents 的启发：

- 保留 `bash_run` 作为兼容工具，但内部统一为 `ExecutionRequest/Process`；
- 未来 `linux_exec`、本地 shell、容器 shell 共用生命周期协议；
- 平台差异放在 Provider，不扩散到 Agent Loop 和 UI。

### 3.2 环境级权限和 Shell 环境策略

Codex 新增并强化了按环境解析权限配置的能力：

- 每个 `EnvironmentConfig` 具有已解析的 permission profile；
- Ready 环境可以覆盖 thread 权限；
- 从 thread 继承的 Guardian 环境限制为只读；
- Shell 环境变量过滤策略随所选环境生效；
- 显式环境变量值不会出现在调试输出中。

相关提交：[per-environment permission profiles](https://github.com/openai/codex/commit/1873e947f804074d99d9537a418b5e4ffde6901f)、[per-environment shell variable policies](https://github.com/openai/codex/commit/6c108912eeacabfc82723bf44f8a23f6e2f86585)。

这是对 DAgents Linux channel 设计最有价值的变化之一：权限不应只属于 Agent 或全局 Node，也应属于“执行环境/通道”。

建议 DAgents 未来采用：

```text
Agent Policy
  ∩ Channel Binding Policy
  ∩ Remote Environment Policy
  ∩ Shell Environment Policy
```

同时禁止把远程环境变量和 secret 直接写入 Agent prompt、snapshot、SSE 或普通日志。

### 3.3 Guardian V2 和安全审批链

Codex 在这段时间将 Guardian V2 接入 App Server，并连续完善：

- thread 风险采样和 risk score snapshot；
- 高风险动作的自动 review；
- Guardian 与 permission profile 的结合；
- `request_permissions` 走统一 Guardian approval；
- Guardian 审核会话与父扩展隔离；
- 审批中的 turn 取消语义；
- MCP tool call 的严格自动 review。

代表性提交：[安装 Guardian V2](https://github.com/openai/codex/commit/3360f4a909a920d2e534a63c508d98e91fe6655a)、[统一权限请求审批](https://github.com/openai/codex/commit/53f3fa749659498fa24c81da8fde5440fa7bba7f)、[MCP 严格自动 review](https://github.com/openai/codex/commit/4e5a08feb63f79e407c86f69a78dc8c7ef115d88)。

对 DAgents 的启发：

- 远程 Linux 命令不能只依赖命令字符串规则；
- 应将风险分类、审批原因、执行环境、权限 profile 和审计绑定在同一个 execution context；
- `require_approval`、`deny`、`auto` 需要有明确的风险来源和优先级；
- 审批服务不能让 Node 失去取消能力；
- 高风险远程命令需要比本地工作区命令更严格的默认策略。

### 3.4 Exec Server 远程认证和可观测性

Codex 加强了远程 Exec Server：

- workload identity 使用异步 auth-header 解析；
- 每次远程环境 registry request 可刷新 managed credential；
- 远程启动时加载 cloud configuration bundle；
- request trace context 可以穿过 exec-server relay；
- executor 的 network policy decision 被发送回控制端审计；
- 网络策略审计进入 log-only telemetry，不污染持久会话日志；
- code-mode gRPC listener 墠加 health endpoint。

相关提交：[workload identity for remote exec-server](https://github.com/openai/codex/commit/fb5aa093e0657c940e8ffd1dd055d22b92d67dfc)、[exec-server trace context](https://github.com/openai/codex/commit/4861236f06d0df397436531b4aa3d7fa6975959c)、[network policy audit](https://github.com/openai/codex/commit/15fde8c1f2d48812c1ad3b5d2fb7a1e7da4053fa)、[log-only telemetry](https://github.com/openai/codex/commit/899d1715c87a504ce4c9ec85c2fd7753e33a7be4)。

对 DAgents 的启发：

- Linux channel 的连接认证应支持可刷新凭据，而不是把 token 永久放在连接配置中；
- 远程执行事件需要携带 trace/request/session/agent/channel 关联信息；
- 网络策略决定属于审计 telemetry，不应混入 Agent 会话正文；
- Exec Server 应提供 health/status，而不是只依赖 SSH TCP 连接是否成功。

### 3.5 MCP 和 Hook 扩展

Codex 增加了 MCP tool handler 对 hooks engine 的支持：

- hook 可以发现同步 MCP tool handler；
- 支持把嵌套事件字段展开到 MCP 输入；
- MCP 输出继续经过 hook output contract；
- hooks/list 返回 MCP server/tool 元数据；
- 不支持的 SessionEnd MCP hook 会给出启动警告。

相关提交：[MCP tool handler in hooks](https://github.com/openai/codex/commit/85fc4def358b7df21883e72ae8dda43a0f572f32)。

此外，Codex 还加入 MCP protocol discovery metrics，并改善 MCP 启动协调和 tool catalog cache。

对 DAgents 的启发：

- Linux channel 未来可以被包装为 MCP，但底层执行仍应经过统一 Provider；
- Hook/Skill/MCP 都不能绕过 Agent binding、policy 和审计；
- 能力发现要带 server/channel/tool 的来源元数据；
- 不可用的外部能力不应阻止 Agent 启动，应显示 offline/degraded 状态。

### 3.6 会话、持久执行和 TUI

Codex 在会话管理方面新增或强化：

- persistent `codex exec` thread 使用分页 history；
- resume/fork 可以复用分页历史和 fork ancestry，而不复制完整 transcript；
- TUI 支持 `/cd`、`/pwd` 和 `/cwd`；
- 切换工作目录时保留会话历史，但重新加载目标目录的配置、指令、权限、hooks 和 file search；
- 活跃任务、排队任务、后台 terminal、远程环境或不兼容权限 profile 时拒绝切换；
- TUI 可以编辑排队消息并显示 resume/fork 状态。

相关提交：[persistent exec paginated history](https://github.com/openai/codex/commit/c4941302c73c6322b153bba13ac0a9f4396301d6)、[TUI working-directory commands](https://github.com/openai/codex/commit/ed32158e90ef872c5eef96baf2f14feac70aee6e)。

对 DAgents 的启发：

- 远程 channel 的工作目录切换需要重新解析 channel/binding policy；
- 不应在活动命令或后台任务期间静默切换执行根；
- session history 和 execution environment 可以分离；
- resume/fork 应使用分页或增量历史，避免大 transcript 全量复制。

### 3.7 诊断、Windows 和本地可靠性

Codex 的 `codex doctor` 得到较大增强：

- 检查 `CODEX_HOME` 和 worktree 磁盘空间；
- Windows 检查 Git worktree 是否位于 trusted Dev Drive；
- 检查 endpoint、代理、TLS、CA、解析和超时问题；
- 识别代理认证失败和未使用系统代理；
- 增加 endpoint protection checks；
- 已删除 workspace 不再阻止 doctor 启动。

相关提交：[storage diagnostics](https://github.com/openai/codex/commit/6efcdad4c3c167741ac3791766152c15b03e3653)、[network diagnostics](https://github.com/openai/codex/commit/c8ddb210d2429cacacf86593e157114b00634f13)、[Windows endpoint protection](https://github.com/openai/codex/commit/c7a95f84b389d64bce0cc6dbd2d893fd5a0577c3)。

另有 Windows sandbox deny-read 规则、外部编辑器 buffer 与 sandbox writable path 隔离等加固。

对 DAgents 的启发：

- Linux channel 应有明确的 `test/status/health`，并区分 DNS、TCP、SSH host key、认证、shell 和命令执行失败；
- Node 诊断可以参考 `codex doctor`，输出可操作的修复建议；
- Windows Node 的远程 Linux provider 不应假设本地 Bash 存在；
- 工作区、外部编辑器临时文件和 sandbox 路径需要明确隔离。

### 3.8 其他可见变化

## 5. 对 DAgents 的优先级建议

### P0：直接影响当前 Linux channel/Shell 设计

1. 将执行权限从“Agent policy”扩展为“Agent + execution environment/channel policy”。
2. 统一 `ExecutionContext`，关联 agent、session、turn、tool call、channel、approval 和 risk。
3. Linux channel 增加可操作的 health/status/test 分层诊断。
4. 远程命令输出和审计事件与普通会话正文分层，避免污染上下文。
5. 连接认证支持 credential version、刷新和连接池淘汰。

### P1：执行质量和可靠性

1. 本地 Bash、远程 Linux、容器共用 Process/Output/Cancel 生命周期。
2. 增加 environment-specific shell variable policy。
3. 增加高风险远程命令的统一审批和风险原因。
4. 为持久执行和大历史增加分页/增量读取。
5. 增强 Windows/Linux 目标环境的诊断和降级提示。

### P2：扩展生态

1. 让 MCP/Skills/Hook 调用统一经过 capability binding 和审计。
2. 增加 Exec Server health、trace context 和 network policy audit。
3. 评估 Guardian 类独立风险评估器，但应先稳定 DAgents 的 policy/HITL 契约。

## 6. 本次判断

本周期最值得 DAgents 借鉴的不是 Codex 的某个单独工具，而是它把“执行环境、权限、审批、网络策略、审计和远程 transport”逐渐收敛成一个有身份和生命周期的 Environment/Exec 模型。

DeepSeek Harness 本周期没有代码变化，因此继续作为插件化和 capability seam 的架构参考；Codex 则成为 DAgents Linux channel、Shell/PTY、执行安全和远程诊断的主要实现参考。
