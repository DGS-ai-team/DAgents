# Agent workspace file API

Desktop and Node share the local filesystem. Node provides workspace metadata and staged write control for an existing, non-archived Agent; file contents do not travel through its workspace HTTP API. Paths are workspace-relative. The root `.dagents` namespace, special files, path escapes and unsafe links remain inaccessible through workspace operations.

* `GET /v1/agents/{agent_id}/workspace?path=...` returns `{ "path": "...", "entries": [...] }`. Each entry has `name`, `path`, `is_dir`, `size`, `modified_at`; regular files also have an absolute Node-side `file_ref`. The listing does not read file contents or calculate revisions.
* `GET /v1/agents/{agent_id}/workspace/location` returns `{agent_id,root}` to the native bridge. It requires the `X-Dagents-Native-Workspace: 1` invocation marker. The marker is a call convention, not authentication or a multi-user security boundary.
* `POST /v1/agents/{agent_id}/workspace/writes` prepares an operation with JSON `{path,mode,kind,expected_revision,size}`. `mode` is `create` or `replace`; `replace` requires the original SHA-256 revision. `kind` is `text` (16 MiB maximum) or `import` (1 GiB maximum). The response contains `{operation_id,staging_root,staging_path,staging_identity,expires_at}`. Only the native layer receives staging paths.
* `POST /v1/agents/{agent_id}/workspace/writes/{operation_id}/commit` accepts JSON `{size,sha256}`. Node checks the operation, Agent, workspace, staging identity and content, prepares a same-directory temporary file, acquires the shared workspace coordinator, rechecks the target version and publishes atomically. Success returns `{path,name,size,revision,file_ref}`. Create collisions and stale target revisions return 412; a busy workspace returns 409 after bounded waiting.
* `POST /v1/agents/{agent_id}/workspace/writes/{operation_id}/cancel` cancels an uncommitted operation. A commit already in progress returns 409; a completed commit reports `committed`. The native caller must wait for the original commit result instead of claiming cancellation prevented a completed write.

Regular-file entry and commit result `file_ref` values are local absolute paths usable by model tools. Staging allows at most 32 active operations and 2 GiB of reserved content, with a 15-minute operation lifetime. Startup, periodic expiry and shutdown reclaim owned staging files. The completed-result cache keeps at most 256 entries; repeated successful commits return the result while retained. An evicted, expired or pre-restart operation ID cannot be committed again. Missing operation status after an uncertain response requires inspecting the current file while retaining the draft, not an unconditional write retry.

Desktop reads bounded contents locally after resolving the current Agent workspace through Node. Complete reads are capped at 16 MiB and return a strong SHA-256 revision; large text uses 256 KiB chunks with weak size/mtime revisions for read-only continuity. A complete chunk is not a write baseline: obtain a full read and its strong revision before enabling editing. Rust writes text to the Node-created staging file, or streams a native-picker-authorized source file into it, then sends only metadata to commit. It validates the staging file identity before truncation. Drag-and-drop or clipboard `File` fallbacks are bounded at 16 MiB over IPC; native file selection supports the larger import limit and progress/cancellation. No workspace binary HTTP fallback remains.

Markdown uses a sanitized reading view with a source/edit toggle. Workspace rendering bypasses the chat Markdown cache so growing chunk prefixes are not retained globally. Save-as uses a native dialog and copies from an authorized local handle; when a draft is open it exports the draft. Editing preserves UTF-8 BOM and the dominant newline style. Failed, conflicting or uncertain writes retain the draft. A source that grows into a read-only preview keeps its stored draft and exposes a separate draft export action. Draft deletion requires a confirmed save without newer edits or explicit user discard. Coordination covers cooperating Node tools and Desktop commits; external processes can still race between version checking and atomic publication. Historical media and model-provider transfers are separate from workspace I/O.
