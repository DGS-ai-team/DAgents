# Agent workspace file API

The Node workspace API remains available to API clients for browsing and editing an existing, non-archived Agent's workspace. Paths are workspace-relative and URL encoded. `.dagents` is private Agent state and is hidden from these endpoints. Directories, special files, paths outside the workspace, and Windows drive/ADS/UNC forms are rejected or omitted. Uploads and writes have a shared 16 MiB limit.

* `GET /v1/agents/{agent_id}/workspace?path=...` returns `{ "path": "...", "entries": [...] }`. Each entry has `name`, `path`, `is_dir`, `size`, `modified_at`; regular files also have an absolute Node-side `file_ref`. The listing does not read file contents or calculate revisions.
* `PUT /v1/agents/{agent_id}/workspace/file?path=...` writes raw bytes. Existing files require `If-Match: "<sha256>"`; new files require `If-None-Match: *`. Missing preconditions return 428; stale revisions and create collisions return 412. Success returns JSON `{path,name,size,revision}` and the new quoted `ETag`.
* `POST /v1/agents/{agent_id}/workspace/upload?path=...` accepts raw bytes and creates a new file only; it returns 200 with `{path,name,size,revision,file_ref}` and an ETag.

The upload response `file_ref` and regular-file entry `file_ref` are absolute Node-side paths and can be passed to model tools. File operations use a root-bound filesystem handle so path traversal and symlink swaps cannot escape the selected workspace. The Node serializes file writes through its shared workspace coordinator so Agents sharing a workspace coordinate with tool writes.

Desktop uses the Node API for directory listings and writes (`PUT`/`POST`); those Node endpoints remain available independently to API clients. Desktop file contents are read locally by Tauri commands after Rust asks the authenticated Node client for the current Agent workspace location. Native reads are capped at 16 MiB and return a SHA-256 revision for save conflict checks. The WebView does not receive a general-purpose path-reading command or the workspace root. The location endpoint requires the `X-Dagents-Native-Workspace: 1` invocation marker, which is not an authorization boundary; normal Node authentication and Agent checks still apply.

Markdown uses a sanitized rendered reading view with a source/edit toggle. Non-text files are previewed through the native full-read limit and can be saved through the native file dialog, which copies from the validated local workspace file handle rather than assembling the file in browser memory. If a text draft is open, save-as exports that draft content; otherwise it copies the current disk file. Node writes remain subject to ETag conflict checks and the 16 MiB write limit.
