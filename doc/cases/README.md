# 落地案例（`doc/cases/`）

本目录用于收录 **不同场景下的部署与使用实践**：业务背景、配置取舍、观测到的效果与限制等，供他人在类似场景下对照参考。

与 **`doc/`** 根目录下的 **契约/架构类** 技术说明（如 **`api-reference.md`**）分工如下：

| 类型 | 位置 | 侧重 |
|------|------|------|
| **规范与接口** | **`doc/*.md`（与本目录平级）** | 与代码行为对齐的约定、流程与字段说明 |
| **场景案例** | **`doc/cases/`** | 真实或接近真实的落地叙述、效果数据、踩坑与复现条件 |

## 新增案例时的约定

1. **文件名**：使用 **ASCII** 英文小写 + 连字符，例如 **`on-prem-offline-agent.md`**，避免跨平台与自动化脚本编码问题。  
2. **单篇结构建议**（可按需删减）：  
   - **场景与目标**：谁在用、要解决什么问题；  
   - **环境与版本**：OS、Python/发布包版本、关键依赖；  
   - **配置与架构**：环境变量、网络拓扑（是否经 Register Center、是否 A2A 等）；  
   - **过程与结果**：关键步骤、量化或定性效果、截图/日志片段（注意脱敏）；  
   - **限制与后续**：已知边界、未解决问题、可改进点。  
3. **敏感信息**：勿写入密钥、内网主机名、未脱敏日志；可用占位符说明。  
4. **维护**：新增或重命名案例文件后，在本 **`README.md`** 下方 **案例索引** 表中补一行，便于浏览。
